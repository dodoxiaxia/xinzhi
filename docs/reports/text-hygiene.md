## 起因和修复位置

- RSS 解析把多行作者列表作为一个 `creator` 文本写入。抽样包内以题录链接域名分组，Wiley 956 个换行，AHA 7 个。现在在 `refresh_feeds.py` 折叠行间空白，同时规范失败重用的 RSS 作者缓存。
- 雷达存档的 PMID `41878868` 通过 `data/translations.json` 的 `pmid:41878868` 取得中文标题。翻译脚本之前只检查是否包含中文，遇到 U+FFFD 仍可保存并被永久命中缓存。现在干跑统计 `invalid_cached`，有损条目和新题名共享补译批次上限。旧值保留到收到通过校验的译文。模型失败时保留旧缓存。既有题名缓存键和匹配逻辑沿用原规则。
- 对只读线上样本按同一规则复查，雷达延迟包的 387 个译名均有效，独立雷达存档的 12,598 个译名中有 1 个无效。完整私有缓存的无效总数未知。定时完整刷新每次最多 60 个付费翻译批次，启用翻译的快速刷新每次最多 1 批。样本中已知的 1 条占用其所在批次的 1 个名额。
- 全文精读 `PMC13740100` 的主要结果来自 `daily_fulltext.py` 生成的 `sections.findings.text`。现行长度、中文、引文和数字校验可接受 U+FFFD。PR 正文附该生成端的精确补丁建议。已有线上条目需要重新生成或按源文核对后修复。
- 合成样本定位了可逆异常的漏口：RSS 标题与摘要解析、PubMed XML 与存档题名解析、Crossref/Europe PMC 摘要清理此前依赖 XML/HTML 的单层解码或原样取节点文本。序列化直接保留剩余转义、实体及误解码字节。现在在各来源第一次产生纯文本时复用 `text_hygiene.py`。速览与标题翻译在解析模型 JSON 后、校验与入库前使用同一套规则，速览引句仍须通过逐字证据校验。源信息不足时，审计保留告警，以便从原始来源恢复内容。

## 11-17 的 037/035

11-17 的首页样本未能复现。检查了上述离线数据、当前线上首屏与所有引用的数据分片。线上纯文本中有 88 次独立 `037`/`035` 数字候选，其中 87 次在摘要、引文或正文中，1 次在效应量中。标题和速览短句里没有。历史首页包和对应原文不在样本中，因此没有把这 88 次计作异常。

`\342\200\224` 是 UTF-8 的 em dash，三字节合并可恢复为 `—`。`\037` 和 `\035` 实际对应 U+001F 和 U+001D。离线测试验证了这两种控制符替换为空格，并验证只有同 ID 同字段的可信原文能逐字对齐到横线时，才将裸数字计为异常。真实试验编号、样本量和独立数字可以保留。原文缺失时无法确认其含义。

## 复查

在有 Node 和离线测试依赖的检出目录执行：

```sh
python3 scripts/fixtures/build_browser_data.py data
python3 scripts/build_public.py
python3 scripts/audit_text_hygiene.py --check
python3 scripts/test_text_hygiene.py
python3 scripts/test_text_hygiene.py --check-built
```

已有构建可以通过 `--public-dir` 和 `--data-dir` 任选一个或同时指定。提供 `--dash-reference <path>` 可使用 `{"123":{"title":"Cardiac MRI — CT"}}` 这样的独立来源文本，并在 `dash_reference_comparisons` 查看参与比较的字段值数量。审计报告按数据范围、异常、字段和写入端分组。构建后的测试套件在审计非零时失败；干净检出目录由单元测试生成带异常的公开包来验证退出码。定时发布工作流沿用自己的现有测试清单。

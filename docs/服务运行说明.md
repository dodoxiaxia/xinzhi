# 心知 (Xinzhi) - 本地知识与编辑服务运行说明书

> **适用场景**：AI 医疗＋心血管每日精选/每周共读站本地持久化后端与编辑台  
> **服务技术栈**：Python 3.9+ 标准库（`http.server`、`sqlite3`、`hmac`、`secrets`），零第三方外部依赖  
> **当前基准日期**：2026-09-29  
> **部署定位**：科室本地试用版（单编辑账号），尚未接入 Google Workspace 组织认证  

---

## 一、 架构与设计原则

本服务实现了文献从 **真实候选导入 $\rightarrow$ 编辑审核草稿 $\rightarrow$ 门禁核验发布 $\rightarrow$ 公开日报导出与撤回** 的完整闭环，并将 **科室内部共读记录** 进行独立持久化存储。

```
outputs/xinzhi/
├── service/                   # [新建] 本地服务后端包
│   ├── server.py              # 多线程 HTTP 服务、静态白名单与 API 路由
│   ├── db.py                  # SQLite WAL 存储层、表结构与审计日志
│   ├── auth.py                # 口令初始化、常量时间比对、限流与 CSRF 防护
│   ├── import_data.py         # 幂等按 doi/url 导入 feeds.json 真实候选
│   └── tests/                 # [新建] 完整集成测试套件
│       └── test_service.py    # 13 项安全、权限、幂等与持久化测试
├── editor/                    # [新建] 现代临床编辑工作台 (安全转义)
│   ├── index.html             # 编辑台单页应用结构
│   ├── editor.css             # 继承全局 style.css 的编辑界面补充样式
│   └── editor.js              # DOM 安全渲染 (textContent)、会话与 CSRF 处理
├── .local/                    # [运行时生成 · 静态完全阻断]
│   ├── xinzhi.db              # SQLite 数据持久化文件 (WAL 模式)
│   └── admin-token            # 自动生成的本地编辑管理员口令 (权限 0600)
├── public/                    # 现有公开包静态文件 (仅公开此目录及首页、样式)
├── data/                      # 原始数据源 (URL 无法直接访问)
└── docs/                      # 架构文档与验证说明
```

### 核心安全准则
1. **静态资源显式白名单**：URL 仅放行首页（`/`、`/index.html`、`/style.css`、`/icon.svg`）、`/public/*` 与 `/editor/*`。严禁通过 URL 访问 `data`、`scripts`、`docs`、`service`、`.local`、父级目录或符号链接文件。
2. **公开读取层物理白名单**：公开接口 `/api/public/articles` 与 `/api/public/briefings` 严格执行字段白名单过滤（`PUBLIC_ARTICLE_FIELDS`），绝不向外暴露审核人（`reviewer`）、来源核对标记（`source_checked`）、内部共读笔记（`notes`）或系统审计日志。
3. **安全门禁发布机制**：文章发布要求中文学术题名、导读摘要、临床局限性与警示、审核人非空，且必须明确勾选“已核对原文来源”，证据依据等级不可为仅索引元数据（`index`）。
4. **即时撤回下架**：撤回操作立即将文章状态标记为 `withdrawn`，公开日报与全量文章接口立即不可见。
5. **身份安全与防伪造**：除登录接口外，所有编辑端接口均要求本地 `HttpOnly; SameSite=Strict` Cookie，所有写操作（POST/PATCH/PUT）严格比对 Origin 与会话关联的 `X-CSRF-Token`；绝不信任请求 Host 或伪造的 `X-User` 头部作为身份凭证；登录失败引入 60 秒 5 次限制的 IP 限流。

## 二、 服务启动与运行方式

### 1. 启动本地服务
在 `outputs/xinzhi` 目录下（或根目录下指定相对路径）执行：

```bash
# 标准启动方式 (默认端口 8766，绑定本地回环 127.0.0.1)
python3 service/server.py --port 8766 --bind 127.0.0.1
```

控制台将输出如下提示信息（**仅打印密码文件绝对路径，绝不打印密码明文**）：

```text
====================================================================
心知 (Xinzhi) AI医疗+心血管每日精选/每周共读服务已准备就绪
管理员密码文件绝对路径: /Users/.../outputs/xinzhi/.local/admin-token
密码来源: 本地自动生成并受权限保护 (0600)
本地数据库路径: /Users/.../outputs/xinzhi/.local/xinzhi.db
静态文件根路径: /Users/.../outputs/xinzhi
--------------------------------------------------------------------
服务监听地址: http://127.0.0.1:8766
编辑端入口:   http://127.0.0.1:8766/editor/
公开端入口:   http://127.0.0.1:8766/public/
公开日报接口: http://127.0.0.1:8766/api/public/briefings?date=2026-09-29
====================================================================
```

### 2. 获取管理员密码
- 若启动前已设置环境变量 `XINZHI_ADMIN_TOKEN`，服务将优先使用该值；
- 若未设置，系统自动生成 32 字节高强度随机口令，保存在受保护文件 `.local/admin-token` 中。
- 查看口令命令：
  ```bash
  cat outputs/xinzhi/.local/admin-token
  ```

### 3. 非 loopback 绑定安全拦截机制
- 默认状态下，服务仅允许绑定本地回环（`127.0.0.1`、`localhost`、`::1`）。
- 若尝试绑定 `0.0.0.0` 或局域网 IP，服务将直接退出拦截，避免在未接入正式企业认证前意外将端口暴露在外网。
- 确需跨机调试时，必须**同时**显式提供 `--allow-network` 参数与 `XINZHI_ADMIN_TOKEN` 环境变量：
  ```bash
  XINZHI_ADMIN_TOKEN="YourStrongSecretToken" python3 service/server.py --port 8766 --bind 0.0.0.0 --allow-network
  ```

## 三、 候选数据幂等导入

从真实候选源 `data/feeds.json` 导入文献候选到 SQLite 数据库：

```bash
python3 service/import_data.py
```

### 导入行为说明：
- **按 DOI / URL 双索引去重**：若文章已在数据库中，**严格保留已有人工编辑内容**（中文题名、核心导读、局限性、审核人、核对标记）以及发布状态（已发布、草稿或撤回），仅在原始元数据字段为空时补充缺失项。
- **不自动发布**：新导入文章状态全部初始为 `candidate`（待审候选），证据依据初始为 `index`（仅索引元数据），不凭空捏造研究结论。
- **审计记录**：每次导入均向 `audit_logs` 表记录新增篇数与保留篇数。

## 四、 接口规范清单

### 1. 公开端接口（无需认证）

| 方法 | 路径 | 参数 | 描述 |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/public/articles` | 无 | 获取所有处于已发布状态的文章，按发布日期降序。严格仅返回公开白名单字段。 |
| `GET` | `/api/public/briefings` | `date=YYYY-MM-DD` | 获取指定日期（默认 Asia/Shanghai 当前日期）发布的精选文章，严格仅返回白名单字段。撤回文章立即排除。 |

#### 公开字段严格白名单（`PUBLIC_ARTICLE_FIELDS`）：
- `id`: 文章标识
- `title`: 英文原始题名
- `title_zh`: 中文学术题名
- `url`: 期刊原文链接
- `doi`: DOI 标识
- `source`: 期刊或订阅源名称
- `source_date`: 原始发表日期
- `category`: 分类方向（AI医疗 / 心血管 / 交叉研究）
- `summary`: 经过人工审核的核心导读与结果摘要
- `limitations`: 临床局限性与风险警示
- `study_type`: 研究类型（RCT / 队列 / Meta分析等）
- `evidence_basis`: 证据依据等级（abstract / fulltext）
- `published_date`: 正式发布日期（YYYY-MM-DD）

> **安全保证**：`reviewer`（审核人）、`source_checked`（核对标记）、`notes`（内部研讨笔记）、`audit_logs`（审计记录）绝对不包含在公开输出中。

---

### 2. 编辑端接口（除 login 外需 HttpOnly 会话 Cookie 及 CSRF 防护）

| 方法 | 路径 | 鉴权要求 | 说明 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/editor/login` | 限流 + 常量时间比对 | 提交 `{"token": "..."}`。成功后下发 `HttpOnly; SameSite=Strict` 会话 Cookie 并返回 `csrf_token`。 |
| `POST` | `/api/editor/logout` | 会话 Cookie | 注销服务端会话并下发清除 Cookie 标头。 |
| `GET` | `/api/editor/session` | 可选 Cookie | 查询当前会话是否有效，有效时返回当前会话的 `csrf_token`。 |
| `GET` | `/api/editor/articles` | 会话 Cookie | 获取文章列表。支持参数：`status` (all/candidate/draft/published/withdrawn), `category`, `search`, `page`, `page_size`。 |
| `GET` | `/api/editor/articles/:id` | 会话 Cookie | 获取指定文章的完整编辑信息（含原始元数据与审核字段）。 |
| `PATCH` | `/api/editor/articles/:id` | 会话 Cookie + CSRF | 保存草稿。仅允许修改：`title_zh`, `summary`, `limitations`, `study_type`, `evidence_basis`, `reviewer`, `source_checked`。禁止篡改原始题名/链接/日期。 |
| `POST` | `/api/editor/articles/:id/publish` | 会话 Cookie + CSRF | **发布门禁核验**：要求中文标题、导读、局限性、审核人非空，`source_checked=True`，且 `evidence_basis != 'index'`。发布成功后打上当前 Asia/Shanghai 日期。 |
| `POST` | `/api/editor/articles/:id/withdraw` | 会话 Cookie + CSRF | **即时撤回下架**：将状态改为 `withdrawn`，公开端立刻不可见。 |
| `GET` | `/api/editor/notes` | 会话 Cookie | 查询内部共读研讨记录列表（按更新时间降序）。 |
| `GET` | `/api/editor/notes/:key` | 会话 Cookie | 获取指定 key 的内部研讨记录。 |
| `PUT` | `/api/editor/notes/:key` | 会话 Cookie + CSRF | 保存或更新指定 key 的内部研讨记录。公开层绝不开放此接口。 |

## 五、 编辑工作台使用指引

访问 `http://127.0.0.1:8766/editor/`：
1. **身份认证**：输入 `.local/admin-token` 中的口令登录。登录后在 Cookie 中保存会话。界面明确标注“单编辑账号本地版，尚未接入Google Workspace”。
2. **文献候选筛选**：在“候选与文章库”选项卡中，可按发布状态（待编辑候选 / 草稿 / 已发布 / 已撤回）或输入关键词检索真实候选文献。
3. **编辑审核与门禁**：点击“编辑审核”弹窗：
   - 查看只读的原始题名、信源期刊、DOI 与原文跳转链接；
   - 填写中文学术题名、研究类型、导读与主要终点摘要、局限性与临床警示；
   - 将证据依据从“仅索引元数据 (index)”修改为“已核对摘要 (abstract)”或“已精读全文 (fulltext)”；
   - 勾选“已完成信源与原文真实性核对”并填写审核人姓名；
   - 点击“审核并通过发布”完成成刊；若门禁校验未通过，界面将明确提示未达标的具体项。
4. **内部共读记录**：切换到“内部共读记录”选项卡，可按稳定的 Key（如 `weekly-2026-w39`）记录领读人、共读临床问题、两面性讨论与科室共识。
5. **公开日报实时预览**：切换到“公开日报预览”选项卡，选择日期即可实时核验公开访客所见视图，确认内部审核字段已完全脱敏。

## 六、 自动化测试执行与验证

测试套件位于 `outputs/xinzhi/service/tests/test_service.py`，无需额外配置，直接使用 Python 标准库运行：

```bash
# 执行全部测试
python3 service/tests/test_service.py -v
```

### 测试覆盖内容：
1. `test_01_unauthenticated_cannot_access_editor_apis`: 未认证请求编辑端读写接口与内部记录均返回 401。
2. `test_02_login_rate_limiting_and_logout`: 错误密码 401，正确密码下发 HttpOnly 会话，登出后凭证失效。
3. `test_03_csrf_restrictions`: 伪造 Origin 或缺少 `X-CSRF-Token` 的写操作均被 403 拒绝；合法凭证顺利通过。
4. `test_04_import_data_idempotent_preserves_edits`: 首次导入后进行人工编辑与发布，再次导入同一数据源，人工编辑字段与发布状态 100% 完好保留。
5. `test_05_publish_gatekeeping_validation`: 缺少必填字段、未勾选来源核对或证据依据仍为 index 时拒绝发布 (400)；全部满足后发布成功。
6. `test_06_published_in_briefing_and_withdrawn_disappears`: 发布后出现在公开日报与全量文章，撤回后两处接口立即消失；白名单过滤杜绝内部字段。
7. `test_07_internal_data_and_token_cannot_be_read_publicly`: 公开访问内部笔记接口报 404；直接通过 URL 访问 `.local/admin-token`、`.local/xinzhi.db`、`service/`、`data/` 均被静态白名单坚决拦截 (403)。
8. `test_08_path_traversal_and_symlinks_rejected`: 路径穿越（`..`）与符号链接文件均返回 403；合法静态文件正常 200 返回。
9. `test_09_database_persistence_across_restarts`: 数据库连接重建与服务重启后，已发布文章状态与内部共读笔记依然存在。
10. `test_10_network_binding_guardrail`: 试图绑定 `0.0.0.0` 但未设置 `--allow-network` 时主动拦截并报错退出。
11. `test_11_untrusted_headers_and_body_size_limit`: 伪造 `X-User` 无法绕过认证；超大请求体 (>1MB) 触发 413 保护。
12. `test_12_rate_limiter_blocks_after_5_failures`: 连续 5 次登录失败后精确封锁 IP (429)。
13. `test_13_import_actual_workspace_feeds`: 对工作区真实 `data/feeds.json` 执行真实全量导入，56 篇候选全部无误落库。

## 七、 生产环境升级建议（上线前备忘）

1. **协议安全**：当前本地版本使用标准 HTTP Cookie；正式上线时必须配置 HTTPS 反向代理，并将会话 Cookie 属性追加 `Secure` 标记。
2. **企业身份认证**：当前为单账号密码文件模式；正式科室协同应平滑升级为 Google Workspace OAuth 2.0 / OIDC 登录，废弃静态共享口令。
3. **中文导读数据沉淀**：主代理或临床审阅团队应基于期刊原文摘要与全文精读，持续填写真实、严谨的中文导读与局限性分析，绝不引入虚构模型幻觉内容。

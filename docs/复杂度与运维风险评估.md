# 心知项目复杂度与运维风险评估

心知的整体复杂度为中高。公开部署是 Cloudflare Pages 六文件，主要难度来自代码、抓取数据、模型缓存、编辑数据库和私有文献快照之间的状态协调。当前应优先完善响应超时、调度隔离、运行证据和同步完成门禁，再处理性能与内容桥接。

本次评估以 2026 年 10 月 7 日的 xinzhi 服务为主，同时检查 AI- 文献库依赖。代码风险基于 v13.6 工作树；线上内容数量来自成功运行 [37593501961](https://github.com/dodoxiaxia/xinzhi/actions/runs/37593501961) 的固定 state。已知问题不因离线测试通过而消失。

## 架构与规模

| 层次 | 组成 | 主要维护难点 |
|---|---|---|
| 公开页面 | Pages 六文件，单个 public.js 约 8.14 MB | 全年数据加载、移动端解析与筛选 |
| 在线服务 | Pages Worker、KV、公开摘要来源、模型提供商 | 网络超时、互斥、费用软阈值与结果核验 |
| 内容生产 | GitHub Actions、RSS/PubMed、main 人工稿、私有 state | 来源降级、时间预算、发布与数据保存一致性 |
| 编辑服务 | 本机 Python/SQLite 编辑台 | 本机发布与公网发布衔接 |
| 私有文献 | AI-、Mac 母库、Drive、私有快照 | 原件哈希、LFS、回读回执和唯一执行者 |

核心代码约一万行，app.js、Worker 和本机 server 各承担较多职责。线上快照包含 82 个信源、856 条当前候选、1,219 条公开题录、12 篇摘要核对导读、15 篇未经人工核验的 AI 速览、12,636 条历史雷达题录。公开题录范围与私有库规模是不同指标。

## 优先风险与处理路径

P1 表示应优先处理的稳定性或完成判断问题，P2 表示容量、观测或业务衔接问题。

| 优先级 | 卡点或断点 | 触发与影响 | 处理路径 |
|---|---|---|---|
| P1 | 旧定时请求占用同一并发组 | 被忽略的 fast 请求仍可能替换合法 pending 刷新 | 本补丁隔离 ignored 并发组；平台侧继续核实旧 Cron 停用 |
| P1 | 旧摘要路径只给响应头设超时 | 上游正文停顿后请求长期挂起；串行提纲进一步放大延迟 | 将旧 resolveMeta 路径接入包含正文限制的总阶段超时，给前端增加等待期限 |
| P1 | KV 计数和互斥非原子 | 并发请求丢计数或重复调用模型，软阈值不能保证费用封顶 | 平台费用告警；需要硬上限时引入原子协调存储 |
| P1 | 摘要补全只在整批结束时保存 | 步骤被预算终止时已取得结果丢失，下次又处理同一队首 | 小批次原子 checkpoint、逐条预算和队列轮转 |
| P1 | 文献三端完成门禁缺少 CSV 回读 | PDF 三侧回执齐全时仍可能把母索引不同步的任务标记 synced | 将每端母索引内容证据纳入 synced 判断 |
| P1 | 文献原件和 LFS 取用问题 | 两份实体 PDF 与母索引 SHA 不符；27 个检出对象为正确 LFS 指针，下游原读取路径会拒绝 | 核对原件版本，保留索引证据；为 LFS 建立受支持的对象读取路径 |
| P1 | 文献云迁移缺少配置与账本 | 云端没有原 Mac 路径、默认 OPML、ledger 和完整回执，迁代码不足以接续任务 | 迁移配置和运行状态后切换唯一 owner；沿用现有调度 |
| P2 | 绿色运行掩盖降级 | 来源失败或可选模型步骤失败仍可用旧缓存构建成功 | 本补丁输出 pipelineStatus、sourceHealth 和固定 warning；巡检读取最终证据 |
| P2 | Pages 成功但 state 保存失败 | 公网与下一轮恢复数据不一致 | 保留 deployed 事实，同时将整条流水线标为 degraded |
| P2 | 发布后缺少自动公网验收和回滚材料 | 静态上传成功不能证明域名、运行配置或模型正常 | 本补丁增加只读公网验收和上一成功发布文件 artifact |
| P2 | 编辑台发布到公网未闭环 | SQLite 的 published 状态不直接进入 Pages 构建 | 明确本机发布范围；通过审核稿白名单导出接入唯一发布入口 |
| P2 | 首屏与筛选数据增长 | 单包约 8 MB，重复构建检索文本和筛选集合导致弱网弱机停顿 | 先测移动端长任务，再缓存检索字段并按需加载历史数据 |

代码定位：旧超时和 KV 在 `edge/_worker.js` 的 `tryFetch`、`resolveMeta`、`bump`、`gate`；批处理在 `scripts/archive_details.py`；构建与发布在 `scripts/build_public.py`、`scripts/ci_daily.py`、`.github/workflows/daily.yml`；三端完成门禁在 AI- 的 `zcode-workflows/sync_receipt.py`。离线 fixture 已复现正文无限等待和并发 KV 丢计数。

## 文献核验结果

AI- 本地母索引共 1,336 条：1,305 份实体哈希匹配、27 个 LFS 指针 oid 匹配、2 份实体 SHA 不符、2 个标注待复核的缺失版本。两份实体差异对应母索引物理第 1280、1281 行的 AIp2600248 与 AIltr2600179；不能直接将索引改成检出文件的哈希。

另有 263 条出版日期为空，263 个 PDF 路径未入该母索引。后者包括 43 份内容已在索引、16 个 LFS 指针和 204 份尚未核验身份与历史用途的实体。数量本身不能决定是否新增入库。下游缓存与上游母索引还存在版本差异，ready 应补充快照年龄与来源提交。

## 定期 CI/CD 与巡检

现有 GitHub 发布工作流处于 active，每天北京时间 05:17 完整刷新，每两小时 :07 轻量刷新。每日心知运维巡检已启用，只在新故障、明显降级或需要用户处理时通知。巡检通过连接的 GitHub读取 state 和对应 Actions；若不能取得最新运行或最终 artifact，会明确监测范围受限。

本分支增强项合并后生效：PR 与每次既有定时刷新先执行只读离线 CI，固定 SHA 只恢复 state 的 data/public，执行 Python、服务、Worker/UI、公开白名单构建和打包；质量失败阻断发布。发布前保留上次成功 state 的六文件与 manifest，发布后检查首页、只读配置接口及当轮发布的四个可读取静态文件哈希。_worker.js 与 _headers 属平台配置，HTTP 文件哈希不证明它们的实际运行字节或行为。

公网检查分别记录 healthy、degraded、unverified。网络不可达记录未核验；模型配置齐全及最近提供商响应不证明生成结果有效。fast 没有内容变化时不拿新的构建时间戳与旧公网页面做哈希比较。运行证据留在 pipeline-final artifact，回滚材料保留 30 天。

回滚时先在 Cloudflare Pages 选择已知有效的 Production 部署，核对首页及静态文件；若需重新上传，使用 previous-release artifact 中 public 下的六文件，仍经原发布入口和权限执行。公网恢复与 state 恢复分别验证；state 恢复需固定预期 SHA 的 lease，避免覆盖未观察到的并发更新。不要直接强推旧 state 或运行历史初始化脚本。

## 处理顺序

先合入 CI、调度隔离和运行证据增强；随后修复正文超时和摘要 checkpoint。文献侧先核对原件与三端完成门禁，再完成唯一执行者迁移。编辑台公网桥接、LFS 全文路径和私有题录扩展需沿用各自的访问与内容边界。性能优化以移动端实测为依据。

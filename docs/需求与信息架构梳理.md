# 心知：需求与信息架构

2026-09-30更新：当前实现和发布状态见 `docs/当前交付状态.md`，v7改动与下一步见 `docs/v7优化核验与后续路线.md`。下列需求保留原始讨论背景，历史条数和自动化进度不能当作当前验收结论。

## 1. 谁用、做什么
| 角色 | 要做的事 | 站点应提供 |
|---|---|---|
| 科室同事（读者） | 花 5 分钟知道最近有什么值得读；晨会/共读时有材料可讨论 | 每日精选、每周精读、晨会清单 |
| 编辑（施军等） | 从大量新文献里挑、核对、发布；控制质量与工作量 | 候选池、核对状态、发布流程（后台） |

当前原则：每日精选展示已按标注范围核对的导读；文献雷达与文献库可公开浏览自动聚合题录、原摘要和明确标记的未核对AI速览，阅读层级不能混淆。

## 2. 栏目定位（v2.1 调整后）
- **今日精选**（首页）：按精选日期分组的信息流，每篇含中文导读、证据边界、共读问题。历史日期自动沉淀，不再只是“3 篇静态卡片”。
- **本周精读**：期次列表 + 本周状态。每周五发布 1 篇有可核验全文的论文精读；本周尚未发布时明确显示“尚未发布”，不再假装每周都有。第 01 期为体例示范（2025 年论文）。
- **文献雷达**：自动候选与公开摘要浏览，数量以当前页面为准。读者可加入晨会单；无已核对导读的条目不提供“微信群文案”。
- **文献库**：科室 PDF 索引（仅题录，未读全文），用于检索查重。
- **信源状态**：维护者排查用，放页脚。

## 3. 工作量（需要你确认的现实约束）
| 环节 | 现状 | 估算 |
|---|---|---|
| 抓取与初筛 | 自动（RSS/PubMed，每日 08:00），零人工 | 0 |
| 中文初稿 | GLM-5.3-Flash 生成，仅用公开题名与摘要 | 0（付费/额度自查） |
| 来源核对 | 目前由 Codex 对照期刊页面完成，非医生 | 每篇约 5–10 分钟（AI）+ 医生终审未做 |
| 每周精读 | 需要可获取的全文，人工/AI 通读、交叉核查 | 每期 1–2 小时，全文获取常是瓶颈 |
所以：每日 3–5 篇是自动化上限；医生终审若要做，建议只对“每周精读”和被加入晨会单的文献做。

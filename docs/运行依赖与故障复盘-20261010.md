## 二、本次发现与处理

### 1. state 保存失败，导致当天运行结果丢失（已修复）

- 证据：[运行 38010683523](https://github.com/dodoxiaxia/xinzhi/actions/runs/38010683523)（10/10 08:49 启动的完整刷新）。发布成功，但最后的 `git push --force-with-lease` 被拒（stale info）。
- 原因：每日全文精读在付费请求前通过 GitHub API 写入检查点。08:52:43 的一次检查点写入在 GitHub 端已生效，但客户端 30 秒超时，未记录新的 state SHA；最终保存仍用旧租约，于是被拒。
- 后果：state 停在含一条 `started` 预留的检查点；为防止重复计费，当天不再生成全文精读，线上显示“今日已更新 0 篇”。
- 修复：新增 `scripts/save_state.py`。租约被拒时，只有当远端新增的提交全部是已知的检查点提交，且只改动检查点文件，才把这些文件合并进本次 state 后重推；其他写入者仍会被拒。测试见 `scripts/test_workflow.py`。

### 2. 每天重复为同一批无法通过核对的全文付费（已修复）

- 证据：state 账本中 PMC13634977、PMC13644689、10.2196/89936 在 10/09 和 10/10 都被重新生成并判为 invalid。
- 修复：`daily_fulltext.py` 跳过此前任一天已判 invalid 的来源，每日 8 次调用额度留给新文献。测试见 `test_daily_fulltext.py`。

## 确认的代码问题及修复

| 问题 | 触发和影响 | 修复 |
|---|---|---|
| 旧源码发布缺少当前 main 校验 | Actions checkout 使用事件提交；旧运行重跑、构建期间 main 推进时，仍可上传旧代码。state 的 lease 只保护 state，不能阻止之前的 Pages 上传。 | checkout 后和上传前分别读取远端 main，与事件 SHA、本地 HEAD 比较；不匹配或远端不可用就停止。 |
| 被忽略的外部请求共用发布并发组 | workflow 级 `daily-refresh` 包含 ignored-dispatch；无效请求也能占用或替换该组的 pending 正式更新。未据此宣称已经发生实际取消。 | 串行组移到真正执行发布的 refresh job。旧请求通知仍存在，平台侧停止触发后才能消除它们。 |
| runner 拒绝 manual_needed | Worker 以 manual_needed 结束无 PDF 来源的查询，runner 的结果白名单缺少此值，抛出 invalid_result 并中止本批。已通过真实 Worker 与 runner 的离线联合夹具复现。 | 接受该终态，正常记录结果并继续领取其它任务。 |
| 前十条延后任务遮挡后续任务 | 领取每次只查两页、每页五条，没有继续游标。即使队列信号发现第十一条可执行任务，runner 仍会退出且反复空跑。 | 授权接口返回分页游标，runner 有界继续扫描；每批最多十次领取、执行五篇，拒绝重复或异常游标。 |

当前 main 校验只保护包含该修复的新工作流。更早的历史工作流没有此代码，不能通过重跑它们安全恢复；应在最新 main 重新触发。远端检查与 Pages 上传不是跨平台原子事务，仍需结合串行发布和实际部署记录判断结果。

## 仍需运行配置或后续集成解决

1. 全文队列目前关闭。Cloudflare 和 GitHub 的 FULLTEXT_ASYNC_ENABLED 属于两套配置；调度器职责、资源权限及真实 OIDC 领取/回传必须成套验收，不能只打开网站侧开关。前次 xinzhi-cron 部署权限拒绝记录仍是历史证据，本轮没有直接核验或更改 Cloudflare 账户权限。
2. 旧外部 fast dispatch 仍每两小时出现：本轮读到 08:07、10:07 运行，只有通知 job 执行，正式 refresh 被跳过。它们不会更新内容且仍消耗 runner；触发器归属和停止动作需在平台配置中确认，本轮未修改现网 cron。
3. GitHub cron 不能视为精确时钟。每日完整刷新计划为 05:17，最近一次完整刷新运行 37710594611 实际于 08:59 启动；网站应按实际完成时间说明更新状态。
4. 合法 DOI 不保证存在云端可访问的 PDF。现有机构浏览器、订阅获取与正式 GitHub/Drive/Mac 三端归档没有由这条队列接通。生产 NEJM 示例目前是 manual_needed；等待不会自行补齐。

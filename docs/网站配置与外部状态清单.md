# 网站配置与外部状态清单

2026-10-10 同步。以下是可版本管理的配置契约，不是 Cloudflare/Muse 账户的完整导出或灾备快照。证据基线与限制见 [同步总账](云端协同同步总账-20261010.md)。

| 对象 | 当前约定/来源 | 恢复与核验方式 |
| --- | --- | --- |
| 正式域名 | https://learn.dryz.info/ | 现有 Pages 域名；DNS/TLS 实际记录需在受控账户核对，历史建站方案不证明当前值 |
| Cloudflare Pages 项目 | dryz-xinzhi；daily.yml 唯一网站发布入口 | 恢复主线代码和 state，检查发布回执及公网版本；不重复创建项目 |
| main/state | main 代码、配置约定、人工文档；state 私有数据及成功构建 | 先固定两个 SHA，禁止用旧 main 数据覆盖 state，禁止恢复 state 时覆盖 main 代码 |
| 完整刷新 | daily.yml：17 21 * * *，北京时间次日 04:47 | GitHub schedule 可能延迟；看真实 refresh job，不以 ignored-dispatch 成功代替刷新 |
| 轻量刷新 | 外部 :07 每 2 小时派发 + daily.yml `37 */4 * * *` 兜底 | gate 限最短 170 分钟，实际约每 4 小时；手动 fast 勾选 force 跳过间隔；不新建重复生产定时器 |
| AI 全文精读 | XINZHI_LLM_ENDPOINT、XINZHI_LLM_MODEL、XINZHI_LLM_API_KEY | 前两项为 Actions vars，密钥为 Actions secret；保留 state 预算账本，默认 8 篇（`XINZHI_DEEP_READING_TARGET`）；周榜每日调用上限 `XINZHI_WEEK_MAX_CALLS`（默认 80） |
| 全文下载 | PDF_DOWNLOAD_ENABLED=true，QL_KV 绑定及既有下载认证配置 | 名称/接口见 PDF下载接入.md；实际密钥与 KV 内容不进源码 |
| Muse 桥接 | MUSE_FULLTEXT_ENABLED=true，独立 MUSE_FULLTEXT_KEY | 保存在 Pages Production 与 Muse 私密配置；/api/muse/protocol 可检查启用条件，不能据代码断言运行时已启用 |
| 互斥消费者 | GROK_FULLTEXT_ENABLED、FULLTEXT_ASYNC_ENABLED 关闭 | Muse 模式避免旧消费者同时领取；旧 Grok 代码存在不等于当前启用 |
| Muse 原件核验 | muse-review.yml：23 * * * *；GitHub OIDC | 只核验已有原件，不访问出版社、不写正式三端；recheck_doi 可单篇重核 |
| Muse 核验即时触发 | 可选 Secret MUSE_REVIEW_DISPATCH_TOKEN（细粒度令牌，仅 xinzhi 的 Actions 读写） | 收到新原件即派发 muse-review.yml；未配置时只靠每小时定时 |
| Muse 下载调度 | 对话中保持未创建 | 与 GitHub 核验 cron 分开；本次不启用新任务 |
| Muse 私有收件箱 | **Muse 文献收件箱**，链接见 Muse网站接入.md | 仅所有者；不是正式 mac文献-三端同步；上传后单独核实 ACL |
| 私人库与正式归档 | dodoxiaxia/AI-、Macmini、正式 Drive | 原归档所有者负责；xinzhi 下载可用不等于 archive.complete |

密钥、密码、Cookie、租约、临时下载 URL、私人索引、受限 PDF 和运行数据库不放入本次 GitHub 同步。需要灾难恢复时分别使用提供商支持的受控备份/恢复流程，不能仅 clone xinzhi 就恢复外部登录态、KV 与 Muse 执行器。

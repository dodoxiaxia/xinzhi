# 网站配置与外部状态清单

2026-10-10 同步。以下是可版本管理的配置契约，不是 Cloudflare/Muse 账户的完整导出或灾备快照。证据基线与限制见 [同步总账](云端协同同步总账-20261010.md)。

| 对象 | 当前约定/来源 | 恢复与核验方式 |
| --- | --- | --- |
| 正式域名 | https://learn.dryz.info/ | 现有 Pages 域名；DNS/TLS 实际记录需在受控账户核对，历史建站方案不证明当前值 |
| Cloudflare Pages 项目 | dryz-xinzhi；daily.yml 唯一网站发布入口 | 恢复主线代码和 state，检查发布回执及公网版本；不重复创建项目 |
| main/state | main 代码、配置约定、人工文档；state 私有数据及成功构建 | 先固定两个 SHA，禁止用旧 main 数据覆盖 state，禁止恢复 state 时覆盖 main 代码 |
| 完整刷新 | daily.yml：17 21 * * *，北京时间次日 04:47 | GitHub schedule 可能延迟；看真实 refresh job，不以 ignored-dispatch 成功代替刷新 |
| 轻量刷新 | 外部定时器 `7 */2 * * *` 派发 daily.yml（`mode=fast`）+ daily.yml `37 */4 * * *` 兜底 | 仓库 `workers/cron-dispatch` 已与线上脚本对齐：cron `7 */2 * * *`，派发 `daily.yml`，正文 `{ref:'main', inputs:{mode:'fast'}}`。Actions 不部署这个 Worker，合并不会改线上定时器。gate 限最短 170 分钟，实际约每 4 小时；手动 fast 勾选 force 跳过间隔；不新建重复生产定时器 |
| AI 全文精读 | XINZHI_LLM_ENDPOINT、XINZHI_LLM_MODEL、XINZHI_LLM_API_KEY | 前两项为 Actions vars，密钥为 Actions secret；保留 state 预算账本，默认 12 篇（`XINZHI_DEEP_READING_TARGET`）；周榜每日调用上限 `XINZHI_WEEK_MAX_CALLS`（默认 150） |
| 全文下载 | PDF_DOWNLOAD_ENABLED=true，QL_KV 绑定及既有下载认证配置 | 名称/接口见 PDF下载接入.md；实际密钥与 KV 内容不进源码 |
| Muse 桥接 | MUSE_FULLTEXT_ENABLED=true，独立 MUSE_FULLTEXT_KEY | 保存在 Pages Production 与 Muse 私密配置；/api/muse/protocol 可检查启用条件，不能据代码断言运行时已启用。下载角色已退出，旧领取/回执/上传/恢复入口在过渡期仍可用 |
| Muse 下载角色收口日期 | 默认 2026-12-12；可用 MUSE_DOWNLOAD_RETIRE_ON（YYYY-MM-DD）改显示日期 | 只改变协议页和机器协议里的日期。到点不自动关闭、不删除接口 |
| 旧 Muse 领取/回执/上传开关 | `MUSE_LEGACY_ENDPOINTS_DISABLED`：普通变量（非 Secret），默认不设（关），只认字符串 `true` | 打开后 `/api/muse/claim`、`receipt`、`upload` 在认证前返回 410 `muse_retired`，不读密钥、不碰 KV；request、retry、reader-upload、review、`/api/acquire` 和 `/api/machine/*` 不变。只对新部署生效；回滚为删除或改成 false 后重新发布。不要动 `MUSE_FULLTEXT_KEY` 和 `MUSE_FULLTEXT_ENABLED` |
| 排队超时无人领取转兜底（默认关） | `STALE_QUEUED_FALLBACK_ENABLED`：普通变量（非 Secret），默认不设（关），只认字符串 `true`；`STALE_QUEUED_FALLBACK_HOURS`：整数 1–144，缺省或无效按 6；`STALE_QUEUED_FALLBACK_MAX_PER_WINDOW`：普通变量，整数 1–25，默认或无效按 5；`STALE_QUEUED_FALLBACK_WINDOW_MINUTES`：普通变量，整数 5–60，默认或无效按 10 分钟；KV `library:stale-fallback-window:<index>` 保存窗口已转换数，TTL 为窗口秒数的两倍 | 打开后，从未被领取过（没有 `claimant`、`softFailCount`、`returnCount`、`previousReason`，即 attempts=0）且排队满阈值的 `queued` 任务，在兜底领取或按 `to-download` / `failed-awaiting-fallback` 列表时被改写为 `failed`，`reason` 为 `queue_unclaimed`，并记 `autoFallback`（`at`、`hours`、中文原因）。其中 `journal` 来自转换时的题录，`openAccess` 仅按静态 DOI 前缀表提示 `yes` 或 `unknown`（`openAccessBasis` 为 `doi_prefix` 或空），不发外部请求、不保证可用，兜底端领取后仍核验文件。下载端领取不触发这个转换。关闭时不读 KV、不写任何记录。只对新部署生效；回滚为删除或改成 false 后重新发布。已转成的任务不会自动改回待下载 |
| PDF 备份到 R2（只写，默认关） | 绑定变量名 `PDF_ARCHIVE`（R2，私有桶，不开 r2.dev 公开访问；桶名与绑定由人在控制台逐个核过再加，仓库不含任何绑定配置）；运行时开关为 KV `QL_KV` 里的键 `cfg:r2_archive_enabled` | 两个条件**同时满足**才写：有 `PDF_ARCHIVE` 绑定，且开关键的值恰好是字符串 `1`。默认关：键不存在、值不是 `1`、读 KV 失败都算关；开关读取在每个实例内缓存 60 秒。写入点只有两处，都是核验通过后写入 KV `library:pdf:<sha256>` 的地方：`librarySave`（开放获取/GitHub 取回、读者上传和机器上传核验通过）和 `machineReplacePdf`（核验通过的替换）。未核验的候选件不备份。写入在响应返回之后的 `ctx.waitUntil` 里做，失败只记一行固定文字，不影响响应。对象键 `pdf/sha256/<64位十六进制>.pdf`（内容的 SHA-256）；先 `head`，已有就跳过，不覆盖；`put` 带 `sha256` 校验，元数据只有 content-type、`sha256`、`size`，不含 DOI、标题、令牌。本阶段**不从 R2 读取**，下载仍走 KV。关闭：把该键删除或写成其他值，最多 60 秒停写，不需要部署，桶和已有对象可保留；彻底移除代码需一次部署。存量回填：`scripts/r2_backfill_check.py` 只读，只核对本地 PDF 的 SHA-256 并打印报告，没有任何写 R2 的路径；真要写入是单独的后续步骤，须先报 ddx，且在桶和绑定确认之后 |
| 请求与错误统计（Analytics Engine） | 绑定变量名 `METRICS`（Analytics Engine，数据集 `xinzhi_api`）；运行时开关为 KV `QL_KV` 里的键 `cfg:metrics_enabled` | 两个条件**同时满足**才写：有 `METRICS` 绑定，且开关键的值恰好是字符串 `1`。默认关：键不存在、值不是 `1`、读 KV 失败都算关；开关读取在每个实例内缓存 60 秒，关掉后最多 60 秒停写。只统计 `/api/*`，每个请求至多一条，写入走 `ctx.waitUntil`，失败不影响响应。字段：blob1 路由（固定路径清单，其他 `/api/` 路径记为 `/api/other`，不含查询串）、blob2 方法、blob3 状态码、blob4 JSON 错误里的 `error` 码（无则空；路由抛异常记 `exception`）；double1 耗时毫秒、double2 固定为 1；index1 同路由。不记录令牌、口令、DOI、标题、IP、User-Agent、机器名。绑定由人在控制台逐个核过再加，仓库不含任何绑定配置。开启：在 `QL_KV` 命名空间里把键 `cfg:metrics_enabled` 写成 `1`；关闭：删除该键或写成其他值，不需要部署；彻底移除代码需一次部署 |
| 账本影子库（D1，只写，默认关） | 绑定变量名 `LIBRARY_DB`（D1，库名建议 `xinzhi-library`） | 由人在控制台逐个核过再建库、执行表结构（见 `d1/schema.sql`）并加绑定，仓库不含任何绑定配置；没有绑定就完全不碰 D1（连开关也不读）。本阶段**不从 D1 读取**，所有读仍走 KV `QL_KV` |
| D1 影子写开关与镜像范围 | KV `QL_KV` 里的键 `cfg:d1_shadow_enabled` | 两个条件**同时满足**才写：有 `LIBRARY_DB` 绑定且开关键的值恰好是字符串 `1`。默认关：键不存在、值不是 `1`、读 KV 失败都算关；开关读取在每个实例内缓存 60 秒，关掉后最多 60 秒停写。读仍然一律读 KV，D1 只是影子副本，写入走 `ctx.waitUntil`，失败只记固定日志 `'d1 shadow: write failed'`、不影响响应。镜像前缀：文献记录 `library:paper:`、全文任务与队列 `library:job:`/`library:queue:`/`library:grok-job:`/`library:muse-job:`/`library:muse-queue:`/`library:muse-review:`/`library:muse-superseded:`/`library:machine-register:`、全文状态/尝试 `library:attempt:`、网盘归档登记 `library:drive-pending:`/`library:drive:`、索引 `library:machine-index:v1`；不写：`library:pdf:`、`library:muse-candidate:`、`library:lock:`、`library:cap:`、`library:ip:`、`library:machine-rate:`（机器调用方每日配额与计数，属限流计数）、`library:diagnostic:`、`library:muse-review-dispatch`、`ai:`、`lock:`、`cfg:` 及非字符串值。KV 删除只在 D1 打 `deleted=1` 标记并保留原值；对账用 `scripts/d1_kv_reconcile.py`（只读；输出里有一行说明这次 KV 用的是 bulk 还是逐键读取）。对账不一致时，先查 Cloudflare 控制台的操作日志（有人在控制台直接改 KV 不会进 D1） |
| 新全文任务通知（webhook，默认关） | Worker Secret `DOWNLOAD_NOTIFY_URL`（https 地址）与 `DOWNLOAD_NOTIFY_KEY`；运行时开关为 KV `QL_KV` 里的键 `cfg:download_notify_enabled` | 读者点「下载全文」且站内还没有全文、新建了下载任务（`/api/acquire`、`/api/muse/request`、`/api/muse/retry`）时，用 `ctx.waitUntil` 异步 POST 一条 JSON，只含 `doi`、`task_id`、`ts`，请求头 `Authorization: Bearer <密钥>`，超时 3 秒，失败只记固定日志、不影响响应。两个 Secret 缺一、地址不是 https、开关键不存在或值不是 `1`/`true`、读 KV 失败，都不发。同一 DOI 一小时内最多发一次（KV 键 `notify:download:doi:<doi>`，TTL 3600）；全站每个 UTC 小时最多 20 次（键 `notify:download:hour:<YYYYMMDDHH>`，TTL 7200），超出只记日志。只在真要发时才写 KV。Secret 用 `wrangler pages secret put --project-name dryz-xinzhi`（或控制台）填，值不进仓库和聊天 |
| 机器下载令牌 | Secret MACHINE_TOKENS（JSON 数组，见机器下载接口.md） | 每个调用方独立 token 与角色；可逐个 revoked。不把令牌值写入仓库 |
| 机器下载限额 | MACHINE_UPLOAD_DAILY_LIMIT（默认 80）、MACHINE_REQUEUE_DAILY_LIMIT（默认 200）、MACHINE_REGISTER_DAILY_LIMIT（默认 200，登记新 DOI 每天最多新增的篇数） | 按调用方、按日。不使用读者的全站 30 次与每 IP 20 次软闸 |
| 旧共享密钥 | MACHINE_LEGACY_REVOKED=true 时，MUSE_FULLTEXT_KEY 不再能调用 /api/machine/* | 不改变 /api/muse/claim、receipt、upload、retry；这些仍用 MUSE_FULLTEXT_KEY |
| 核销已完成但仍是 queued 的任务 | 普通变量 `MACHINE_RECONCILE_DONE_ENABLED` | 只认字符串 `true`，默认不设。接口 `POST /api/machine/reconcile-done`（仅 fallback 角色）默认只演练；写入要正文 `apply:true` 与本变量同时满足。关闭时只读，不写任何记录。详见机器下载接口.md |
| 互斥消费者 | GROK_FULLTEXT_ENABLED、FULLTEXT_ASYNC_ENABLED 关闭 | Muse 模式避免旧消费者同时领取；旧 Grok 代码存在不等于当前启用 |
| Muse 原件核验 | muse-review.yml：23 * * * *；GitHub OIDC | 只核验已有原件，不访问出版社、不写正式三端；recheck_doi 可单篇重核 |
| Muse 核验即时触发 | 可选 Secret MUSE_REVIEW_DISPATCH_TOKEN（细粒度令牌，仅 xinzhi 的 Actions 读写） | 收到新原件即派发 muse-review.yml；未配置时只靠每小时定时 |
| Muse 下载调度 | 对话中保持未创建 | 与 GitHub 核验 cron 分开；本次不启用新任务 |
| Muse 私有收件箱 | **Muse 文献收件箱**，链接见 Muse网站接入.md | 仅所有者；不是正式 mac文献-三端同步；上传后单独核实 ACL |
| 私人库与正式归档 | dodoxiaxia/AI-、Macmini、正式 Drive | 原归档所有者负责；xinzhi 下载可用不等于 archive.complete |

密钥、密码、Cookie、租约、临时下载 URL、私人索引、受限 PDF 和运行数据库不放入本次 GitHub 同步。需要灾难恢复时分别使用提供商支持的受控备份/恢复流程，不能仅 clone xinzhi 就恢复外部登录态、KV 与 Muse 执行器。

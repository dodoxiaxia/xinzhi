# 机器下载接口

网站是全文下载状态的唯一账本。下载端和兜底机器人通过 `/api/machine/*` 领取、上传、回写和重排；读者页面只反映这里的记录。协议本身公开：`GET /api/machine/protocol`（不需要令牌，不返回令牌）。

Muse 已退出下载角色。旧的 `/api/muse/claim`、`/api/muse/receipt`、`/api/muse/upload` 和读者恢复入口 `/api/muse/retry` 在过渡期保持原样，说明见 [Muse网站接入](Muse网站接入.md)。计划收口日期默认 2026-12-12，可用 `MUSE_DOWNLOAD_RETIRE_ON` 改显示日期。到这一天不会自动关闭，也不会删除接口。需要提前关闭时，设置普通环境变量 `MUSE_LEGACY_ENDPOINTS_DISABLED=true`（只认 `true`，下次发布生效）：`/api/muse/claim`、`receipt`、`upload` 在认证前返回 410 `muse_retired`，`/api/muse/retry` 和读者入口不受影响；`/api/machine/protocol` 的 `legacyMuse.closed` 与 `closedEndpoints` 反映开关状态。机器接口本身（包括旧共享密钥角色）不因此改变。

## 令牌

在 Cloudflare Pages 项目 `dryz-xinzhi` 的 Production Secret `MACHINE_TOKENS` 中保存一个 JSON 数组，最多 20 条。每条只含 `id`、`role`、`token`，以及可选的 `revoked`。不要把真实令牌写进仓库、文档、日志或聊天。

```json
[
  {"id":"dsh","role":"downloader","token":"<32 到 128 位，仅字母数字下划线或连字符>","revoked":false},
  {"id":"fallback","role":"fallback","token":"<另一枚，不能与其他条相同>"},
  {"id":"ddx","role":"reader","token":"<只读调用方>"}
]
```

- `id`：小写字母开头，最长 32 位，字符为 `a-z`、`0-9`、`_`、`-`。上传成功后记在任务的 `source` 和 `caller` 上。
- `role`：`downloader`（下载端）、`fallback`（兜底）、`reader`（只读）。
- `token`：32–128 位，字符为 `A-Z`、`a-z`、`0-9`、`_`、`-`。调用时放在 `Authorization: Bearer <token>`。
- `revoked: true` 只拒绝这一条。其他调用方不受影响。
- 重复的 `id` 或 `token`、字段不合法、数组损坏：调用返回 503 `machine_not_configured`。协议页在这种情况下显示 `configured: false`。

仍可使用原来的共享密钥 `MUSE_FULLTEXT_KEY` 调用新接口，此时调用方记为 `muse`、角色为 `downloader`。设置 `MACHINE_LEGACY_REVOKED=true` 后，这把密钥不能再调用 `/api/machine/*`。旧的 `/api/muse/claim`、`/api/muse/receipt`、`/api/muse/upload`、`/api/muse/retry` 不看这个开关，仍按原来的 `MUSE_FULLTEXT_KEY` 校验。配置表里若某条 token 与共享密钥相同，以配置表为准（已吊销就拒绝）。

| 角色 | 上传 | 失败回写 | 确认放弃 | 领取待下载 | 领取失败任务 | 列表 | 批量重排 | 登记新 DOI | 放弃清单 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| downloader | 是 | 是 | 否 | 是 | 否 | 是 | 是 | 是 | 是 |
| fallback | 是 | 是 | 是 | 否 | 是 | 是 | 否 | 否 | 是 |
| reader | 否 | 否 | 否 | 否 | 否 | 是 | 否 | 否 | 是 |

错误令牌 401 `machine_unauthorized`。已吊销 401 `machine_revoked`。角色不允许 403 `machine_forbidden`。

## 六个对外状态

内部记录仍用原来的状态。列表、领取和回写使用下面这六个名字。

| 对外状态 | 内部状态 |
| --- | --- |
| to-download | `queued`，且未过排队期限 |
| downloading | `running` 或 `uploading`，且租约未过期 |
| uploaded-awaiting-verification | `verifying` |
| done | `available` |
| failed-awaiting-fallback | `failed`、`login_required`、`review`，以及已过期的 `queued` / `running` / `uploading` |
| confirmed-abandoned | `abandoned` |

核验未通过时内部状态仍是 `review`（网站核验任务认的就是这个词）。机器列表把它显示为 `failed-awaiting-fallback`，并带上原因：`invalid_pdf`、`invalid_identity`、`identity_mismatch` 或 `verification_rejected`。这类条目额外带 `claimable: false` 和 `unclaimableReason: "verification_failed"`，表示不能领取、也不能重排。其余列表条目带 `claimable: true`，不带 `unclaimableReason`。不新开对外状态，以免既有客户端（如 `machine_client.py` 的六个状态白名单、文献下载按 `failed-awaiting-fallback` 拉列表）把它们漏掉或判为未知状态。

核验未通过（`review`）的任务不能被兜底领取：领取会跳过它们，保留原来的候选文件和原因，不会改成 `running`。列表里一眼能看出不可领，请不要对它们再调 `claim`。兜底机器人仍可对这个 DOI 直接上传一份新 PDF（走上传检查，不需要先领取）。

失败回写 `POST /api/machine/status` 只接受这些原因：`not_oa`、`han_login`、`han_quota`、`source_blocked`、`wrong_paper`、`other`。`han_login` 在内部记为 `login_required`。`stage` 只能是调用方自己写上的 `han` 或 `yiigle`。Drive 文件 ID 可以省略，以后用只含 `doi` 和 `driveFileId` 的请求补上。

只有 fallback 可以把任务设为 `confirmed-abandoned`。`GET /api/machine/abandoned` 列出这些条目，供每周汇总。

## 上传

`PUT /api/machine/upload`，正文是 PDF，`Content-Type: application/pdf`，请求头 `X-Machine-Doi` 为任务 DOI。也可以 `POST` multipart，字段只能是 `doi` 和 `pdf`，不要全文口令。

上传前用首页文字核对 DOI 和题名（与任务上的题录，或尚无题录时的 Crossref 题名）。这是粗筛，不是 pdftotext：只读第 1 页。读不到、对不上时返回 409，正文里带内部原因码 `reason` 和 `checks`（只说明哪一项没过，不含 PDF 内容）：

| `error` | `reason` | 含义 |
| --- | --- | --- |
| `machine_identity` | `doi_invalid`、`title_too_short` | 任务 DOI 非法，或题名归一化后不足 5 个字 |
| `machine_identity_mismatch` | `page_tree_not_found`、`contents_not_found` | 找不到页树或第 1 页没有内容流 |
| | `objstm_unsupported`、`filter_unsupported` | 页对象在 `/ObjStm` 里但解不开，或内容流用了不支持的滤镜 |
| | `inflate_failed` | `FlateDecode` 解压失败（流末尾多出的换行等多余字节不算失败，会被容忍） |
| | `page_text_empty` | 首页没有任何文字，例如扫描件 |
| | `doi_not_found`、`title_not_found`、`identity_mismatch` | 文字读到了，但缺 DOI、缺题名，或两者都不对 |

读取方式：按文件内的 `N G obj` 重建对象表（后出现的优先），从最后一个 trailer 或 xref 流字典取 `/Root`，沿 `/Pages` → `/Kids` 第一项找到第 1 页；`/ObjStm` 里的对象在第一次需要时解压；内容流按 `/Length` 截取（`endstream` 紧随其后才采信），否则取到 `endstream` 并去掉一个换行；`FlateDecode` 末尾多余字节不会让整段作废。首页字体带 `ToUnicode` 时，按 CMap 把 `Tj`/`TJ` 里的字形码译成文字。

通过的条件仍是 DOI 与题名**都**在首页读到，并按证据强弱记入任务的 `identityLevel`，同样写在上传响应的 `task.identity`：`full`（首页文字里 DOI 和题名都有）；`metadata_doi`（题名在首页，DOI 只在 Info/XMP）；`metadata_title`（首页文字根本读不出，DOI 在首页，题名只与 Info `/Title` 或 XMP `dc:title` 一致）；`doi_only`（首页文字读不出、DOI 在首页、题名无法确认）；`metadata_only`（DOI 和题名都只来自元数据）。首页文字读得出来而题名不在其中时一律 409 `title_not_found`，元数据不能救。除 `full` 外的任何一级都**不会**直接变成 `done`，和 `full` 一样先进入 `uploaded-awaiting-verification`，由每小时的双解析器核验检查全部页面的题名与 DOI。

同一 PDF（相同 SHA-256）在等待核验时再次上传返回 200，`idempotent: true`，不新开任务。等待核验时换一份不同的 PDF 返回 409 `machine_conflict`。已经完成返回 409 `machine_done`。已确认放弃返回 409 `machine_closed`。另一调用方还持有未过期租约时返回 409 `machine_busy`。核验失败后可以重新上传。

### 覆盖已完成的原件（`X-Machine-Replace: 1`）

任务已是 `done` 时，普通上传返回 409 `machine_done`。需要换成另一份原件（例如先前因首页检查过不去而传了改写副本）时，同一个上传请求加请求头 `X-Machine-Replace: 1`：

- 只有 `MACHINE_TOKENS` 里角色为 `downloader` 或 `fallback` 的调用方可用；`reader` 和旧的共享 Muse 密钥返回 403 `machine_forbidden`；值不是 `1` 返回 400。
- 完整重跑上面的首页身份检查和上传检查，不放宽；之后仍走双解析器核验。身份不符照常 409，不改动任何记录。
- 只对已有核验通过原件的 DOI 有效，否则 409 `machine_replace_unneeded`；新文件与现存原件 SHA-256 相同返回 409 `machine_replace_same`；该任务正在核验另一份候选返回 409 `machine_conflict`；另一调用方持有未过期租约（`running`/`uploading`，或核验器租约）返回 409 `machine_busy`；已确认放弃返回 409 `machine_closed`。
- 计入调用方每日上传额度，与普通上传同一计数器。同一份文件重放返回 200 `idempotent: true`，不再计数。
- 记录：任务上的 `replace` 含 `by`（调用方 id）、`at`、`oldSha256`、`newSha256`，响应的 `task.replace` 同。核验通过后写为 `replacedFrom`（再加 `verifiedAt`），并删去临时字段。覆盖前会把当前已是 `done`/`available` 的任务**原样**写入 `library:muse-superseded:<doi>:<旧 taskId>`（含旧 `sha256` 和旧状态），新任务带 `supersededFrom`，以便把提前发表版换成正式版时仍能对上旧记录。
- **核验通过之前旧原件继续可下载。** 通过后站内存档指向新 SHA；旧 PDF 的 KV 条目和 Drive 存档保留，不删除。核验不通过则任务回到 `available`，旧原件不动，并在 `replaceRejected` 里记下新 SHA、调用方和原因。

机器上传不经过读者的全站每日 30 次和每 IP 20 次软闸，也不检查同源。限额是每个调用方每天 `MACHINE_UPLOAD_DAILY_LIMIT` 次，默认 80，允许 1–500，否则 503。只对新进入核验的上传计数；同一份文件的重放、身份不符、冲突都不计数。超限 429 `machine_rate_limit`。

## 领取、列表、重排

`POST /api/machine/claim`，正文 `{"state":"to-download"}` 或 `{"state":"failed-awaiting-fallback"}`。下载端只能领待下载，兜底只能领失败待处理。响应里有题名、`leaseId`、`leaseUntil`，以及开放获取和汉堡入口的地址。**拿到 `task: null` 后，至少等 `Retry-After` 响应头（同值也在响应体的 `retryAfterSeconds`，默认 300 秒）再领，不要立刻重领。** 正在重建索引时（见下文）等待值是 60 秒。领取时把 `claimant` 写成调用方 id。领取兜底任务时，使它变成「失败待兜底」的旧原因（如 `agent_failed`）不再留在 `reason` 里（`reason` 只在 `failed-awaiting-fallback` 和 `confirmed-abandoned` 的条目上出现），而是记入任务的 `previousReason`。过期未回写的任务在列表里显示 `lease_expired` 或 `queue_expired`。

列表 `GET /api/machine/tasks?state=&cursor=&limit=`。`limit` 为 1–50，默认 20。响应里的 `cursor` 为 null 时表示这一状态下没有更多条目。客户端应一直带着返回的 cursor 取下一页。旧的 Muse 领取只看队列前 10 条；机器领取、重排和按状态列任务不再翻全部任务键，而是读一个很小的候选索引（见下文「候选索引」），第 11 条及以后的任务同样能被取到。按状态列任务时，`to-download`、`downloading`、`uploaded-awaiting-verification`、`failed-awaiting-fallback` 四种走索引；`done`、`confirmed-abandoned` 和不带 `state` 的列表仍按任务键翻页（每页最多 100 条键、最多 50 页），它们不在领取路径上，但账本大时每次调用会消耗较多 KV 列举，不要高频轮询。换成索引后，`cursor` 的格式变了：带 `state=` 的列表请用同一次列表返回的 cursor 翻页，旧的 cursor 会得到 400。

网站自己的开放获取路径（站内「获取全文」和重试按钮）取到的 PDF，在进入核验收件区前，先做与机器上传相同的首页身份检查。DOI 或题名对不上（例如预印本与正式版题名、DOI 不同）就放弃这个来源，试下一个；全部放弃后任务回到待下载队列，不会进入 `review`。放弃的来源（网址不含查询参数，最多 3 条）和原因码记在任务的 `oaRejected`，列表条目里也会带上 `oaRejected: [{source, reason}]`，下载端能看出开放获取这条路为什么没走通。

`POST /api/machine/requeue`，正文可含 `dryRun`（布尔）和 `limit`（1–50，默认 20）。把 `failed`、`login_required`，以及已过期的 `queued` / `running` / `uploading` 放回 `queued`。暂停的 DOI 记入 `skippedPaused`，不改状态。核验未通过的 `review` 不重排，也不能被领取（列表里 `claimable` 为 false）；正确做法是直接上传正式版 PDF。`dryRun: true` 只报告会改哪些，不写账、不占每日额度。真正重排的篇数计入 `MACHINE_REQUEUE_DAILY_LIMIT`（默认 200）。额度用尽时 dry-run 仍可查询，执行返回 429。

重排同样不经过读者的 30 次 / 每 IP 20 次软闸。

## 候选索引

KV 免费档每天只有 1000 次列举、10 万次读、1000 次写。早先的领取、重排和列表每次都要把全部任务键列一遍再逐个读取，账本有 2000 个任务键时，一次「失败待兜底」的空领取就要 20 次列举和 2000 次读。现在网站在 KV 里另存一个键 `library:machine-index:v1`，只记还有人可以处理的任务：`queued`、`running`、`uploading`、`verifying`、`failed`、`login_required`、`review`。`available`（已完成）和 `abandoned`（确认放弃）不进索引，它们的任务记录仍不设 TTL，审计信息照旧保留。

- **索引只是候选清单，任务记录说了算。** 领取、重排和列表读到候选后，都会再读任务记录本身核对状态和租约；索引与记录不一致时按记录处理，并顺手改正索引。所有改任务状态的地方（统一的 `musePut`）会同步维护索引；一个请求里改多条（登记、重排）只写一次索引。
- **空领取只读 1 次**（读索引），没有列举。领取到任务也没有列举。一次领取最多核对 20 条记录；重排最多核对 150 条，超过时 `truncated: true`，再调一次即可。
- **首次回填。** 索引键不存在时，第一次机器请求会扫一遍任务键重建它：每个请求最多花约 400 次 KV 操作，把进度存进索引，后续请求接着扫。账本 2000 个任务键时约需 5 个请求，共约 20 次列举、2000 次读、5 次写，之后不再整体扫描。回填期间 `claim` 只能从已扫到的部分领任务，领不到时返回 `task: null` 和 60 秒的 `Retry-After`；`requeue` 和按状态列任务返回 503 `machine_index_building`（带 `Retry-After: 60`），请稍后重试。
- **KV 不是原子存储**，两个请求同时改索引时，后写的可能盖掉先写的一条。索引里多出来的条目会在被核对时清掉；漏掉的条目要靠重建找回：`POST /api/machine/requeue`，正文 `{"reindex":true}`（仅 `downloader` 角色，不能与其他字段同用），反复调用直到响应里 `reindex.ready` 为 true。重建期间索引会先清空，`claim` 返回 `task: null`（60 秒后再试）。
- 超过 7 天没有更新的条目（对应记录的 TTL 已到）会自动清掉。

KV 不是原子存储。领取在写入后会再读一次租约；对不上返回 503 `machine_sync_pending`，调用方应稍后重试，不要另开一篇。

## 登记新 DOI

`POST /api/machine/register`，只有 `downloader` 角色可以调用（含旧共享密钥调用方 `muse`）。`fallback` 和 `reader` 返回 403 `machine_forbidden`，无令牌或错误令牌 401，已吊销 401 `machine_revoked`。

正文是 JSON，只允许一个字段 `items`，每次 1–50 条。超过 50 条整批返回 400 `machine_batch_too_large`，不写入任何东西；空数组或字段不对返回 400 `machine_bad_request`。

```json
{"items":[
  {"doi":"10.1093/eurheartj/ehag570","title":"Example article title","source":"rss-2026-11-12-am","section":"CARDIO"}
]}
```

| 字段 | 要求 |
| --- | --- |
| `doi` | 与其他接口同一套归一化：去掉 `https://doi.org/`、`doi:` 前缀，转小写。 |
| `title` | 必填，去掉标签后不超过 800 字，且归一化后至少 5 个字（上传时要用它核对首页，太短的题名永远传不上去）。 |
| `source` | 自由字符串，用来标记这一批从哪里来，例如 `rss-2026-11-12-am`。1–64 位，字符为字母、数字、`.`、`_`、`-`，首字符为字母或数字。 |
| `section` | 只能是 `MAIN` 或 `CARDIO`，区分大小写。 |

响应固定为 200，每条的结果按输入顺序放在 `results` 里：

```json
{"ok":true,
 "counts":{"registered":1,"skipped":2,"overQuota":0,"rejected":1},
 "results":[
  {"doi":"10.1093/eurheartj/ehag570","result":"registered","state":"to-download","section":"CARDIO","source":"rss-2026-11-12-am"},
  {"doi":"10.1000/old","result":"skipped","reason":"exists","state":"done","where":"ledger"},
  {"doi":"10.1093/eurheartj/ehag570","result":"skipped","reason":"duplicate_in_batch"},
  {"doi":null,"result":"rejected","error":"bad_doi"}],
 "quota":{"limit":200,"used":1,"remaining":199,"resetsAt":"2026-11-13T00:00:00.000Z"}}
```

`result` 有四种：

- `registered`：新登记，状态是 `to-download`，与站长在网站上点选全文一样：写入题录（`manual_needed`）、任务账本和排队指针，之后用现有的 `tasks`、`claim` 流程领取。题名、`source`、`section` 同时记在任务上（列表和领取响应里会多出 `registeredSource` 和 `section`），并另存一份永久记录 `library:machine-register:<doi>`，附登记人和时间。重排后这两项仍保留。
- `skipped`：幂等跳过，不改状态、不重复入队、不占额度。`reason` 为 `exists`（账本里已有，`state` 给出它此刻的对外状态，`where` 为 `ledger`、`paper` 或 `legacy_job`）或 `duplicate_in_batch`（同一批里前面已经出现过这个 DOI，以前面那条为准，后一条的题名、`source`、`section` 被忽略）。`paper` 表示只有题录、没有任务记录，`state` 为 `no-task`，已有全文则为 `done`；`legacy_job` 表示旧的全文任务还在，`state` 为 `legacy-task`。账本里已经有的 DOI 不论处于哪个状态（待下载、下载中、待核验、已完成、失败、已放弃）都不会被改动。失败后需要再下载，请用 `requeue`，不要重新登记。
- `over_quota`：超过当日额度，没有写入。可以第二天再提交，或请站长调高额度。
- `rejected`：这一条本身不合格，不影响同一批里的其他条。`error` 为 `bad_item`（不是对象或带了多余字段）、`bad_doi`、`bad_title`、`bad_source`、`bad_section`。

每日额度按调用方、按 UTC 日（与上传、重排同一天界）计数，**只计新登记的条数**，跳过和被拒绝的不计。环境变量 `MACHINE_REGISTER_DAILY_LIMIT`，默认 200，允许 1–500，否则 503 `machine_not_configured`。额度用尽时，已存在的 DOI 仍然得到 `skipped`，其余新 DOI 得到 `over_quota`，响应里的 `quota` 给出剩余额度和重置时间。

KV 不是原子存储。写入后会再读一次任务；如果同时有别的写入者先建了这个 DOI，这一条按 `skipped` 报告，不覆盖对方。某一条写入中途失败时，这一条留下的内容会被清掉，整个请求返回 503 `library_storage`；之前已经写成功的条数照常计入额度，重试同一批时它们会得到 `skipped`。

如果 `GROK_FULLTEXT_ENABLED` 或 `FULLTEXT_ASYNC_ENABLED` 为 true（别的全文队列在接管），登记返回 409 `muse_owner_conflict`，不写入。只有暂停标记、没有题录和任务的 DOI 可以登记；领取时仍会因暂停而跳过它。

登记不会联网查 Crossref，题名以调用方提交的为准，之后上传 PDF 时拿它核对首页，所以题名要和论文一致。

## 观察计数与领取耗时

网站按调用方、按 UTC 日记录一组观察计数，供对照运行情况，**不设上限、不挡住领取或上传**。计数写在一个 JSON 键里：`library:machine-rate:stats:<调用方 id>:<UTC 日期>`，TTL 2 天，与现有额度键相同。额度键（`upload` / `requeue` / `register`）仍是整数，不会写进这个文档。

| 字段 | 何时加一 |
| --- | --- |
| `claim` | `POST /api/machine/claim` 成功领到一篇 |
| `emptyClaim` | 同一接口返回 `task: null` |
| `upload409` | `PUT`/`POST /api/machine/upload` 返回 409（身份不符、冲突、已完成、他人持有租约等）。401/403/429 不计 |
| `release` | 调用方用 `POST /api/machine/return` 把任务退回待下载 |

KV 增量（每个计数事件）：**+1 读 +1 写**。一次请求只给一个字段加一，因此不会在同一键上写两次。领取成功或空领取各 1 次写；上传 409 另 1 次写。完成记录只是在本来就要写的任务键上多留字段，不另增键。

粗算：一台下载端一天领取 80 次、空领 20 次、上传 409 共 10 次，约 **+110 写 / 天**。免费档每天 1000 次写；现有上传/重排/登记额度键、任务写入和索引维护仍按原路径计算。本项不改 daily-refresh，也不提供读取这些计数的 HTTP 接口。

上传进入核验时，若该 DOI 先前有领取记录，新任务会带上原来的 `claimant` 和 `acquisitionStartedAt`（领取开始时间）。核验通过后这两项仍留在完成记录里。列表、领取和上传响应在能算出来时多两个可选字段（旧客户端可忽略）：

- `claimedAt`：领取开始时间（ISO）
- `claimDurationSeconds`：从领取到上传（`receivedAt`）的整秒数。没有先领取就直接上传时不加这两项。

## 租约到期与 source_blocked 的软重试

只有这两种情况会先退回待下载，并给该篇加一次 `softFailCount`：

- 领取后租约到期（`lease_expired`），包括下次领取扫描到已过期的 `running` / `uploading` 记录时
- 调用方用 `POST /api/machine/status` 报告 `source_blocked`

同一篇累计 **2 次** 这类失败，才进入失败待兜底，供兜底领取。第一次退回时保留原来的 `id`、`createdAt` 和 `queueKey`（FIFO 位置不变），并补回队列指针。第二次进入失败待兜底时，记录仍保留当时的 `claimant` 和 `acquisitionStartedAt`。同一次 `claim` 不会把刚退回的这一篇再领走，下次再领。

从失败待兜底领走的任务会带上 `previousReason`。这类条目（本来就是 `not_oa` 等硬失败，或已经两次软失败后由兜底领走）在租约到期时**不会**回到待下载，而是回到失败待兜底，并保留原来的原因（`reason` / `previousReason`），不会被清掉。

`not_oa`、`wrong_paper`、`han_login`、`han_quota`、`other` 仍一次性进入失败待兜底（`han_login` 仍是内部状态 `login_required`）。排队超过 6 天的 `queue_expired` 也仍是硬失败，不计入上述两次。

已经写在失败待兜底里的旧记录（例如历史上第一次 `source_blocked` 就被标失败的）不会被自动改回待下载；这次只作用于新发生的报告和租约到期。重排会把 `softFailCount` 一并带上，所以次数是按篇累计的。

KV 增量：退回待下载时，在本来就要写的任务键之外，可能多 **1 次写**（补回 `queueKey` 指针）。不新增按日计数键。不改 daily-refresh。

## 覆盖同 DOI 旧任务时写入取代记录

一篇的 KV 任务键始终只有一把 `library:muse-job:<doi>`。直接 `PUT` 上传会走 `museIntake`：新建一条 `verifying` 任务、覆盖这把键，并删掉旧的 `queueKey`。若等到新任务核验通过再去这把键上找旧记录，旧任务（例如失败待兜底）已经整条丢失，往往只在 `machine-register` 键里还看得到旧 `taskId`。

因此，只要 `museIntake` 将要覆盖这把键上的**任何现有任务**，就会先把旧记录**原样**写到 `library:muse-superseded:<doi>:<旧 taskId>`。这包括失败待兜底、`review`、尚未完成的任务，以及用 `X-Machine-Replace: 1` 替换已是 `done`/`available` 的原件（例如把提前发表版换成正式版）：

- 带 `supersededBy`（新 taskId）、`supersededAt`，以及原来的 `reason` / `previousReason`、旧 `sha256` 和旧状态，**不设过期**
- 旧记录里的 `replace`、`replaceRejected` 也原样保留；只有指向七天临时候选副本的 `candidateKey` 不存
- 新任务立刻带 `supersededFrom`（`taskId`、可选 `reason` / `previousState`），不必等核验通过
- 若新任务后来核验失败进入 `review`，再重新上传正式版，会先把这篇 `review` 记录同样归档，新任务的 `supersededFrom` 指向它，并嵌套更早的一环，链不会断
- 被覆盖的失败旧任务因此不再出现在失败待兜底列表，也不能再被领取

不提供单独的 HTTP 读取接口；旧客户端可忽略 `supersededFrom`。本项不改线上已有记录，也不用手改 KV。线上在本项上线前已被覆盖而丢失的旧任务，无法从任务键找回。

KV 增量：每发生一次这样的覆盖，在写入新任务键之外 **+1 写**（归档键），无额外读。

## 续期与退回

仅**当前未过期租约的持有人**可以调用。阅读角色没有这两个接口。请求体为 `{ "doi": "..." }`，也可附带领取时拿到的 `leaseId`（若提供则必须与当前租约一致）。

- `POST /api/machine/renew`：每次把租约延长 20 分钟，但从这次领取的 `acquisitionStartedAt` 起最多 120 分钟。超过上限返回 409 `machine_lease_limit`，不能再续。租约已经到期的不能续，只能重新领取（若该篇因租约到期被退回待下载）或按失败规则处理。
- `POST /api/machine/return`：
  - **下载端**退回**不算失败**，任务回到待下载，保留原来的 `id`、`createdAt`、`queueKey`（FIFO 不变），`returnCount` 加一。同一篇最多退回 **3** 次；第 4 次返回 409 `machine_return_limit`，任务仍留在当前领取人手上，此后只能用 `POST /api/machine/status` 报告失败（或把 PDF 上传）。退回不会增加 `softFailCount`。
  - **兜底角色**的退回（以及任何带 `previousReason`、从失败待兜底领走的条目）**回到失败待兜底**，并保留原来的 `reason` / `previousReason` 和领取人，不会回到待下载，也不计入上述 3 次限额，不增加观察计数 `release`。选择保留退回权限而不是关掉，是为了让兜底可以把领走的篇放回失败待兜底列表，而不会误进待下载。

列表在 `returnCount > 0` 时带上该字段。旧客户端不调用这两个接口即可，行为与现在相同。

KV 增量：续期是任务键 **+1 读 +1 写**。下载端退回待下载是任务键 +1 读 +1 写，另可能 +1 写补回队列指针，以及观察计数 `release` 的 +1 读 +1 写。兜底退回失败待兜底只写任务键（可能另删队列指针），不写观察计数。不新增按日额度键，不改 daily-refresh。

## 开放获取核验未通过

来源为 `open_access` 的任务，核验未通过时：

- **第一次**：任务回到待下载（保留原来的 `id` 和队列位置）。候选 PDF（`candidateKey`）**只留记录、不删除**，并在 `oaRejected` 里记下来源、原因、`sha256` 和时间为证。`oaVerificationFails` 为 1。
- **第二次**（同一篇累计两次）：任务留在内部状态 `review`，对外仍是失败待兜底，但按已有规则 `claimable` 为 false、`unclaimableReason` 为 `verification_failed`，不能领取或重排。候选文件同样保留。

机器下载端或读者上传（`source` 不是 `open_access`）核验未通过的行为不变，仍直接进入 `review`。旧客户端可忽略新增字段。

KV 增量：第一次退回待下载时，任务键 1 次写，另可能 +1 写补回队列指针；**不删除**候选对象（比直接进 review 少一次删除）。第二次与现在一样写任务键。不改 daily-refresh。

## 保存期限

`done` 和 `confirmed-abandoned` 写入时不设过期时间，一直留到被删除。其余状态，包括 `failed-awaiting-fallback`，仍是 7 天。失败任务如果 7 天内没有被兜底领取、重排或重新上传，记录会从 KV 消失，无法再从网站恢复。

## 网站不做的事

汉堡每天能下多少篇、何时改走其他来源，由下载端自己的调度器决定。网站不设这个上限，也没有对应的配置项。调用方可以在状态回写里带上 `stage: "han"` 或 `stage: "yiigle"`，网站只保存这个标记。

# 每日全文精读

右侧“全文精读”复用现有 daily-refresh 流程，随每天北京时间 04:47 的完整刷新更新，每天最多新增 12 篇（上限，仓库变量 `XINZHI_DEEP_READING_TARGET` 可调，1–20）；只收心血管（含心血管 AI）和通用医学 AI 方法学/评测论文，口径内候选不足时不凑数；每次定时轻量刷新会继续补充口径内的论文。GitHub 调度和来源服务可能延迟；界面显示实际更新日期和当天实际篇数；导出至少 1 篇即算完成，当天没有符合口径的论文显示「今日暂无符合口径的精读」，只有生成本身出错才显示原因。初次上线时，若 state 尚无精读数据，源码轻量发布会进行一次有界初始化；此后的轻量刷新只读取缓存。

## 选材与内容边界

仅从第 3 档旗舰和第 2 档重点期刊选材；可用高分候选不足时少发，不用低档期刊补位。同档综合文章类型（指南、试验或系统综述/荟萃分析、原创研究、综述）、心血管与 AI 交叉、近7天榜名次和发表日期。默认每主题优先安排至多 8 席（其余主题没有可用高分候选时可超出），有足够通用 AI 医疗高分候选时预留 2 席。候选范围为近 90 天，仍排除撤稿、更正、研究方案及来信、评论、社论、新闻、病例报告等。不把期刊档或文章类型当作单篇研究的质量审核。

发现候选时是否开放不参与评分。现有生成路径仍要求 Europe PMC 标记开放且有 PMCID、正文完整且身份匹配。仅有题录或待补标记时不生成；出版商 PDF 和人工补回的 PDF 尚未接入此生成路径。

每篇包含研究问题、设计与人群、主要结果、局限与不确定性、临床讨论，附原文证据、段落位置、开放全文和 DOI 链接。全文取回必须同时核对 PMCID、PMID、DOI 和题名；全文过长或不完整则跳过，不用摘要冒充全文。生成内容必须逐段通过引句存在和数字依据校验。

界面不再显示“未经人工审核”这类标签（2026-11-13 的决定）；范围为公开全文正文，不包括补充材料。机械证据核对不能代表医学质量审核或医生终审。原 TAILORED-AF 体例示范保留在历史示范区域，其原始日期不变。

## 无人值守更新

入口是 scripts/daily_fulltext.py --run，由 ci_daily.py 在大存档任务前运行，沿用 Actions 已配置的 XINZHI_LLM_ENDPOINT、XINZHI_LLM_MODEL、XINZHI_LLM_API_KEY。仍保留三条开放全文检索，另按期刊 ISSN 查询近 14 天的旗舰和重点期刊（不限定开放状态，按日期取最多两页）。榜单加分读取 state 上次生成的 data/weekly-board.json，通常最多滞后一天，文件缺失或损坏时不加分，不重跑榜单。

只有确认 state 仓库为私有时，才在同一 data/deep-readings.json 的 `wanted` 字段保留尚不可读的高档题录（包括已尝试但未取得可用公开正文的论文）。按 DOI/PMID 去重，记录优先分、缺全文原因和交接路径：`publisher_oa` 表示来源报告开放、应查找出版商公开 PDF；`manual` 表示尚未确认开放、交现有人工渠道。清单不主动下载 PDF、不访问付费墙，也不公开。

最多保留 60 条；从上次查询最早的候选开始，每天最多用 40 次只读查询检查开放状态。后来在 Europe PMC 开放的论文自动进入可读候选池，精读发布后标为已发布；未发布条目从首次发现满 30 天后停止复查。维护者可在恢复私有 state 的检出目录运行 `python3 scripts/daily_fulltext.py --wanted` 离线导出 JSON。

只使用现有模型，不自动切换供应商。每个北京时间自然日最多“目标篇数 × 2”次模型请求（默认 24 次，包含未通过证据校验的结果），获取公开正文最多“目标篇数 × 5”次。每次输出上限 6000 token，不循环重试；回复被截断或未正常结束只跳过该篇，网络、HTTP 等结果不明的错误才停止当天的付费请求；接近步骤时限时不再发起新请求。

data/deep-readings.json 保存结果与实际状态，data/deep-reading-ledger.json 保存每天的请求记录。付费请求前，使用现有 GITHUB_TOKEN 原子提交这两个文件至私有 state；校验后再保存结果。state 更新仅允许非强制快进，与恢复时 SHA 不符即停止；最新 SHA 回写现有 .local/week-checkpoint-head，供发布后的 state 租约使用。不另建定时任务、不启用其他预生成任务的开关。

同日已达到目标时直接复用；已尝试的 DOI/PMCID 不重复调用。上次请求处于 started 或供应商失败时当天停止，保留已完成篇目并显示实际不足。最近 90 天精读保留历史；原始来源段落及请求账本不进入公开包。公开构建仅投影题录、中文精读、有限证据引句、来源和状态。目录（题名、期刊、日期、标识）留在 `public.js`；正文按 `publishedOn` 的月份写入 `shards/readings-年-月.内容哈希.js`。页面先显示目录，打开某一篇或带 `read=` 的链接时才请求那一个月。未改动的月份文件名不变，浏览器可以继续用缓存。载入失败时阅读面板里可以重试。搜索、筛选和文献阅读面板不请求这些分片。

## 私有 PDF：离线交接与只读预览

在安装了 PyMuPDF 的环境中，将 STATE_DIR 指向已确认私有、已有待补队列的 state 检出目录，并仅暂存已授权持有的原件：

~~~sh
python3 scripts/deep_reading_input.py stage --doi "$DOI" --pdf "$PDF" --state-dir "$STATE_DIR"
python3 scripts/deep_reading_input.py check --state-dir "$STATE_DIR"
python3 scripts/deep_reading_input.py prune --state-dir "$STATE_DIR"
~~~

这些命令不联网、不提交、不推送，并拒绝公开源码检出目录。prune 删除不再待补的输入，已发布的输入保留到发布后满 30 天。清单上限 64 KiB，只允许规范小写 DOI、64 位小写 SHA-256 和实测大小；最多 12 篇、累计 120 MiB、每篇 20 MiB。不接受符号链接、硬链接或 Git LFS 指针；按哈希定位，复核文件及首页 DOI 和题名。每次解析最多 30 秒、200 页；仅取可辨认的正文，最多 120,000 字符，不做 OCR，也不以摘要代替正文。

只读预览仅在确认 state 私有且 Europe PMC 无可用全文时可用。它不接入日更，不配置或调用生产模型，不修改待补状态，也不写入精读、账本、state、KV 或 D1。输入核验失败只返回固定原因码，不调用预览模型；成功仅返回内存中的精读，单条引句至多 25 词、每篇至多 100 词，无私有来源链接。是否持久化和发布另行审核。

原始输入、清单、文件路径、哈希及正文不进入公开构建、分片、两个公开 ZIP 或 CI 工件。最终 state 保存会拦截非私有目标的原始输入；本地学习站 ZIP 可包含原始输入，只在获准的私有环境中保管，不对外分发。

## 验证与恢复

离线验证运行 test_daily_fulltext.py、test_daily_reading_ui.cjs 以及原流水线、公开构建和打包回归。daily-reading-checks 工作流还验证可获取至少 3 篇身份匹配的完整公开正文，不调用模型。

实际生成成功与公开发布成功分别确认。首批运行后读取 state 的 deep-readings.json、last-refresh.json、deployment-status.json 与相应 Actions；以实际篇数和部署结果为准。来源或模型失效时保留有效内容，不更改历史日期，不删除账本来重置请求次数。

生成器 v2 为完整正文的连续证据片段分配固定编号，模型选择编号，系统绑定精确原文，仍逐段检查所有数值。失败的未核对稿仅保存在私有精读数据的 drafts 字段，供后续修复；公开构建忽略该字段。生成器升级时进行一次有界迁移更新，保留当天已有请求记录与限额。

生成器 v3 支持最多 12 个来源片段，数值校验只规范等值的写法（英文数词/月份、千位分隔符和小数精度），不进行数值换算或计算。已保存的未核对稿必须仍与原请求及全文 hash 一致，再次通过同一证据/数值校验才可恢复，不增加模型请求。

## v14.4.1 近似合格稿的无模型修复（2026-10-10）

10-10 当日 4 次模型输出全部被拒，复盘已存草稿：每篇只差一处，如某段多出 1 个证据里没有的数字（“1级肥胖”中的“1”、引自未绑定段落的“39.5%”），或证据条数 15 超过上限 12。另有 1 篇草稿按现行校验已合格，但恢复逻辑只查当天账本，前一天失败的稿件永远不会被恢复。

修复只做删除，不改写、不增加数字或来源：去掉未知或重复的证据编号；证据超过 12 条时优先保留承载本段数字的条目；删除含无证据数字的整句。删除后某段不足原长一半则不发布，保留原错误（例：研究问题段只剩 60/173 字的稿件仍被拒）。修复后必须原样通过现有校验，账本记录 `repairedWithoutModel`。

恢复范围扩展到近 7 天的失败草稿；2 小时快刷运行 `daily_fulltext.py --recover`（不联网、不调用模型），完整刷新仍在调用模型前先恢复。按 10-10 实际草稿离线验证：当日从 0 篇变为 3 篇。

同一篇文章按 PMCID 只出现一次。生成与草稿恢复都先查已存条目的 PMCID，因为条目标识优先用 DOI：早先存下时 Europe PMC 还没有 DOI、后来有了，仅按标识会当成两篇并再次调用模型。公开构建对同一 PMCID 的多条记录按固定规则只留一条：生成时间最早的一条（时间相同取 sourceHash 较小者），缺 DOI 或 PMID 时从被丢弃的那条补上，并在标准错误输出一行警告；私有库不改写。构建不再因此中断。

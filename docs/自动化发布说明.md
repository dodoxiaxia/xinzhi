# 全自动每日更新(GitHub Actions → Cloudflare Pages)

## 它做什么
每天北京时间 05:17(也可在 Actions 页面手动点 Run workflow):
1. 从私有仓库的 `state` 分支恢复数据(data/、public/)
2. 抓 RSS + PubMed → 合并候选 → 增量更新 365 天存档 → 补摘要(Europe PMC/PubMed/OpenAlex/Crossref)→ 翻译新增标题(智谱)
3. 构建公开包,过“体检门槛”(公开文件必须恰好 6 个;radar≥300、library≥1000)
4. 通过门槛才用 wrangler 直接发布到 Cloudflare Pages(项目 dryz-xinzhi);不通过则不发布、旧站不受影响
5. 把最新数据覆盖写回 `state` 分支(每次只有 1 个提交,不累积历史,仓库不会越滚越大)

## 一次性设置(你来做,约 10 分钟)
1. 在 GitHub 新建**私有**仓库(必须私有:里面有 30MB 私有存档)
2. 在 xinzhi 目录:`git init && git add -A && git commit -m init && git branch -M main && git remote add origin <仓库地址> && git push -u origin main`
   (.gitignore 已排除 data/、public/、.local/,这些不会进 main)
3. 播种数据:`bash scripts/seed_state.sh`(把本地 data/ 和 public/ 推到 state 分支)
4. 仓库 Settings → Secrets and variables → Actions:
   - Secrets:`CLOUDFLARE_API_TOKEN`(在 Cloudflare 创建,权限仅“Account · Cloudflare Pages · Edit”)、`CLOUDFLARE_ACCOUNT_ID`(2149f58092e68928a94f3daf34e1c2a5)、`XINZHI_LLM_API_KEY`(智谱 key)
   - Variables:`XINZHI_LLM_ENDPOINT`(https://open.bigmodel.cn/api/paas/v4/chat/completions)、`XINZHI_LLM_MODEL`(glm-5.3-flash)
5. Actions 页 → daily-refresh → Run workflow,手动跑第一次并观察

## 注意
- 首次翻译存量标题请先在本机跑完(translate_titles.py --run --limit 20000),CI 每天只补新增(限 60 次调用)。
- 站点后端的解读 API 用的是 Cloudflare 里的变量,与这里的 GitHub Secrets 是两套,互不影响。
- `editorial/`(人工核验稿)在 main 里,随代码提交;本机更新后 git push 即可,下一次自动构建会用到。
- 某个数据源临时失败:必需步骤失败=当天不发布也不覆盖 state;可选步骤(存档/补摘要/翻译)失败=照常发布。
- 若想暂停自动更新:Actions 页面 Disable workflow。

## 半小时刷新(v13.1)
- 每天 05:17(北京)完整刷新:抓取 + 归档 + 补摘要 + 翻译 + 发布。
- 每 2 小时(每个偶数 UTC 小时的第 7 分):轻量刷新(只抓取 RSS/PubMed 并合并构建),**内容有变化才发布**,没变化不部署。
- 读者页面开着时,每 10 分钟(或切回标签页时)检测新版本,有更新会弹出"内容已更新,点击刷新"。
- Actions 私有仓库免费额度 2000 分钟/月,轻量刷新一次约 1~1.5 分钟,月用量约 1500~2200 分钟,接近上限:如提示额度不足,把 cron 改成 `7 * * * *`(每小时)或只保留 06:00–24:00。

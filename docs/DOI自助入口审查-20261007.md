# DOI 自助入口审查与最小补丁

最初核对的 `main` 为 `bcb7355b2c8a1e3dd3000880df8fcabf474aabd4`，DOI 实现来自 `7f40183b8c81e5f2e8f02846b93b8a83260bf8f4`；两者 DOI Worker 无差异。提交期间 main 新增 `94db8eee5193f06afdf0198b1f378da7d5133a20` 的重试提示，已合入隔离分支并解决冲突。保留 busy/quota/KV 同步的精确 Retry-After 与北京时间提示；机构授权/身份待核状态不显示虚假的五分钟倒计时。本补丁不修改公共题录、前端检索入口、main/state、部署或调度。

## 审查结论

当前已有完整的网页补录缓存功能：口令与来源检查 → Crossref → 固定 GitHub 索引与 PDF → KV 补充题录/文件 → `/api/library` 查询及 `/api/fulltext` 下载。但它没有接入 815 领取账本、Drive/Mac 写入和回读，也没有严格跨云领取。KV 软锁是尽力防重；`fulltextStatus=available` 只表示网站缓存有文件，不证明三端归档或逐页题名/DOI验证。

用户指定 DOI 时 Hamburg 优先的要求仍适用。复用已经归档的原件不属于新获取；GitHub 原件未命中时，直接 Unpaywall/OpenAlex 下载不满足该要求。目前没有支持的 Hamburg 授权执行桥，不能自动控制 Mac Safari。

## 本次补丁

只修改现有 `/api/acquire`，没有第二入口、第二队列、消费者或新持久化服务。

- 继续 Crossref 官方身份解析、GitHub 固定索引/原件复用、既有 KV 缓存和只读下载。`/api/pdf` 不变。
- 删除入口中的 OA 新下载分支。无原件时保留已核题录为 `manual_needed`；明确未领取下载任务，等待 Hamburg、唯一账本和三端接入。
- 已有 pending/review/blocked 记录重复提交直接复用，不再重新请求来源。已缓存成功记录继续验证缓存字节并复用。
- 受保护结果增加 `archive`：`scope=website_cache`、`complete=false`、`executionClaimed=false`、`ledgerChecked=false`，Mac/GitHub/Drive 正式归档回执均 pending。网页文字不再把 KV 保存当成三端完成。
- 来源失败显示 blocked；元数据 403/429 等 upstream 失败保存暂停状态，后续提交不再次请求。元数据请求暂停的恢复须由维护者确认原因已解决后精确清除已有 `library:attempt:<DOI>` 暂停标记；已保存为 manual/review/blocked 的题录需要唯一授权执行者接管，清标记不会自行启动新下载。不得循环重试。该标记仍属于既有 KV 命名空间。
- DOI 拒绝 `../` 与二次编码残留；现有来源/路径白名单保留。补录 PDF 最小 50 KiB，既有大小上限/文件头/EOF/SHA/Git blob 检查继续执行。这些不是双解析器身份验证。

未扩展只读 GitHub 凭据，未新增任何 Secret/OAuth、Cloudflare 资源、网络设置。此前研究的协调器原型已退出交付，未部署、未推送；本分支不包含它。本次只能交付安全的复用/等待路径，不能宣称新文献已自动三端入库。

本轮已实际取回并验证：

- Drive ledger SHA256 `b2a6d3dbf01656c9347646198001cf5a200590bb633d734f4a671174979f2d33`，815 条。
- 既有 DOI `10.1001/jamanetworkopen.2026.37533`：两端 PDF 都是 1,202,764 字节、SHA256 `7234844b6174ea61ee7200f7af83b948a4c7ab6ee42fc58ed47b3f31a1cb04c4`。双解析器遍历 16 页，首页题名和 DOI 均通过。

## 下一步最小接入与验收

1. **唯一执行者**：由原流程负责人确认旧 Grok/consumer 状态，指定唯一现有领取账本的云端 owner。不能把 KV 软锁或本机 fcntl 称为跨云互斥；本补丁不执行领取。
2. **授权浏览器桥**：给选定云 executor 提供受支持的 Hamburg 正常登录会话；登录/验证码/403/429 暂停。不得导出 cookie/口令/签名参数或伪称云端可控制 Mac Safari。
3. **三端写入**：按需由用户在安全界面确认 AI- 精确仓库 Contents 写入、已确认 Drive 私有根写入/回读，以及 Mac 归档/回读桥。接收方仅选定 executor；现有 Pages 只读 GitHub token 保持只读。不另建队列或调度。
4. **先复用验收**：用上述既有 DOI 经实际受保护网站入口读取，核对同 DOI 重入 ID/原始 SHA 不变、无出版商新请求；分别记录网站缓存与正式三侧当前回读。Mac 不在线时必须 pending。
5. **新增验收**：仅在上述 owner/权限/桥均齐备后，先报告目标 DOI，最多一篇且先完成索引与全部历史 ledger 去重。核对 Hamburg 获取、私有暂存头/大小/题名/DOI/双解析器/SHA、三端 PDF 与索引各自原字节回读，最后才 complete。真正缺失的某侧只补该侧。

push 前检查：唯一 `.github/workflows/daily.yml` 的 push 仅匹配 main，refresh job 同样要求 `refs/heads/main`。专用分支不会触发现有生产工作流；不创建 PR 评论、不合并、不部署、不改变调度。

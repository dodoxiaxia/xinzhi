# 一键 AI 解读：部署与运维说明（v13.6）

下列是配置要求，不代表本轮已核实 Cloudflare 实际绑定或模型连通性。Actions 批处理和 Pages runtime 是两套配置；最近 Pages 发布成功只证明部署被接受。

读者在文献详情里点“✨ 一键 AI 解读” → 网站后端（`_worker.js`）取 Europe PMC 公开摘要 → 调你的大模型 API → 校验（引句必须是摘要原文、数字必须出现在摘要里）→ 存入 KV → 所有读者之后直接看到，不再重复调用。内容标注“模型生成 · 未经人工核对”。

## 你需要做的（Cloudflare 后台，约 5 分钟）
1. **建 KV**：Workers & Pages → KV → Create namespace，名字如 `xinzhi-ql`。
2. **绑定**：Pages 项目 `dryz-xinzhi` → Settings → Bindings → Add → KV namespace，变量名填 **`QL_KV`**，选上一步的 namespace（Production 环境）。
3. **变量**（Settings → Variables and Secrets → Production）：
   - `LLM_ENDPOINT` = 例如 `https://open.bigmodel.cn/api/paas/v4/chat/completions`（须 https）
   - `LLM_MODEL` = 例如 `glm-5.3-flash`（示例不是运行时核验证据）
   - `LLM_API_KEY` = 你的 key，类型选 **Secret**（加密，不会出现在网页或公开包里）
   - 可选：`DAILY_CAP`（全站每日读者生成请求计数阈值，默认 150）、`IP_CAP`（每访客每日计数阈值，默认 20）、`MODEL_CALL_CAP`（实际提供商尝试软阈值，默认 300，按 UTC 日），`AI_ENABLED` 设为 `off` 关闭生成（已存解读仍可读）
4. **重新部署**：使用 daily.yml 的同一六文件发布流程；不要用旧版本 ZIP 覆盖新页面和 Worker。
5. 先检查平台只读配置与 GET 缓存/可生成状态；真正生成会调用付费模型，仅在已授权内容工作中验证。

没配好时：网站照常使用，按钮自动隐藏（后端返回未配置）。

## 安全与成本
- key 只在 Cloudflare 的加密变量里；前端只调用同域 `/api/ql`。
- 摘要由服务器自己去 Europe PMC 取，不接受前端传来的摘要，防止有人往共享缓存里投毒。
- 计数：全站与每访客阈值、同一篇 180 秒锁、Origin 同域检查。KV 读改写与锁不是原子操作，不能当作严格的并发费用硬上限；需在账户核实实际调用、KV 用量及平台限流。原始失败重试也可能产生模型调用费用。
- v13.5 不接受请求 hint 作为 PMID/DOI 对应关系，只用匹配的权威记录；模型请求拒绝跳转，鉴权/限流/传输错误不再次调用；短字段执行 60 字上限，失败详情仅返回安全码。

## 运营
- 删除/撤下某条解读：KV 里删除键 `ql:pmid:<号>` 或 `ql:doi:<小写doi>`。
- 所有条目都带 `generatedBy: reader-click`、模型名和时间，可日后批量导出复核，把好的并入 `data/quicklooks.json`。
- 每日批处理 `generate_quicklooks.py` 仍可并存；本地预览（无后端）不显示按钮。
- 公开包现为 6 个文件（新增 `_worker.js`）；`edge/_worker.js` 是源码。

## v10 追加：翻译与多篇综述（同一后端 `/api/ai`，同一 KV、同一限额）
- **摘要中英对照**：详情抽屉“公开摘要”下方的“🌐 翻译摘要”，生成后全站共享，同时补上中文标题。校验：题名与摘要各自保留全部数字及出现次数，允许小数的无损表示等价、英文月份转对应月份；禁止改数、换算或漏数。
- **晨会清单“✨ AI 生成讨论提纲”**：清单里 ≥2 篇时出现；按文献集合缓存。
- **列表页“✨ AI 综述本页前 N 篇”**：对当前筛选结果的前 8 篇做综述速读；同一组文献缓存复用。
- 三个功能共用日上限（DAILY_CAP）和每人上限（IP_CAP）；`AI_ENABLED=off` 一并关闭。翻译/综述缓存键：`tr:v2:pmid:…`、`br:<mode>:<hash>`。
- 未做：追问对话、AI 检索助手（不可缓存、成本与被滥用风险高）。

## 取摘要的回退链（v10 修订）
用户点击 AI 按钮时，后端按顺序找公开摘要，找到即停：Europe PMC → PubMed(efetch) → OpenAlex → Crossref → 期刊 DOI 落地页的公开元数据（citation_abstract / dc.description，最后手段，单篇、仅点击时、带标识 UA、失败不重试）。摘要须 ≥300 字符，来源写入结果（“摘要来源”）。都没有时不生成解读（避免编造），可“只翻译标题”。
每日流水线 `archive_details.py --fill` 也会给 RSS 候选里“有 DOI 无摘要”的条目按 DOI 补摘要，并入公开包。
注意：NEJM/JAMA/AHA 等出版商页面常有反爬，落地页那一步经常拿不到，属预期；读者来信/述评本来就没有摘要。

## v13.5.2 API 热修

公开摘要清洗先识别真实标签，再解码实体，避免把 `<4 mm2 ... >315` 当成 HTML 删掉。PubMed、归档、批处理和 Worker 均保留医学比较符；只从官方数据重新取得缺失文本，不凭残缺缓存补写。

模型响应按固定安全码区分认证、限流、网络/超时、空结果、格式、截断与证据校验，前端不再把所有故障显示成引句/数字错误。模型请求 45 秒超时，摘要来源单次请求 8 秒超时。格式或证据失败最多重试一次；认证、限流和网络故障不重试。截断时只对一次重试扩大输出预算（速览 1200→2400，翻译/提纲 3000→6000）。

翻译使用 `tr:v2:` 新缓存空间，保留旧缓存但不复用旧清洗/校验产生的译文。新结果记录 validationVersion 与来源指纹。维护时依安全错误码定位，不读/输出凭据或提供商响应正文。发布成功仍不证明 Pages 实际模型鉴权与单次读者生成已成功，须另有运行证据。

文献库仍是既有公开题录快照；私有全文库更新桥接尚未完成。网站维护不授权公开私人索引，也不授权向外部模型发送私有 PDF 或内部资料。

## 生产连接诊断（v13.5.3）

2026-10-07 06:59:15–33 UTC 云浏览器对公开 PREVENT 摘要的一次正常翻译未成功，显示 transport_error。这个旧码不能区分 fetch 抛错与提供商 network_error，不能据此认定 DNS、地区、认证或令牌问题。原运行没有保存细分日志，无法事后恢复原异常。

新 Worker 将请求网络与提供商内部网络故障分别分类，先验证 HTTPS 端点；redirect:manual 的 3xx 直接拒绝，不跟随、不读取 Location。每次模型尝试只记固定阶段、错误码、HTTP状态、耗时、超时标志和随机关联ID，不记录 URL、正文、头或原异常。安全记录保存于 KV ai:runtime:last-diagnostic:v1，24小时过期；失败同一固定记录可在 Functions 实时日志中读取。

GET /api/ai?task=status 只读返回配置存在性与最近提供商尝试，不调用模型，不返回配置值。canGenerate 表示配置符合基本要求，不证明真实模型生成成功；response_received 只证明收到可解析提供商结果，仍需独立证据校验。生产日志能力及 runtime 外部网络仍需真实公开摘要调用核验。

## v13.6 公开摘要服务与维护

需求重点是读者快速识别研究结构、准备阅读全文，以及在晨会中逐篇核对不同研究。单篇阅读抽屉的“研究结构与全文核对”显示研究问题、对象、本文设计、比较组、终点、主要结果六项，各项配对应摘要的逐字引文；摘要缺失的信息固定写“摘要未提供”。本文事后分析与母试验 RCT 在提示中明确区分。晨会清单明确选择 2–4 篇后提供同样六项的逐篇表格，保留未取得摘要的列，不排名、不合并效应。固定全文核对清单是待确认的问题，不代表已经发现研究缺陷。

只接受 PMID/DOI 标识；不接受前端正文、上传 PDF、患者资料或自由追问。服务器取权威匹配的公开元数据；新服务检查 PubMed PMID、OpenAlex/Crossref DOI 及出版商 citation_doi 对应关系，拒绝同一论文的 PMID/DOI 重复对照。元数据最多并行两篇，总阶段 35 秒；单次 headers+body 8 秒，正文最多 1 MiB。摘要超过 6000 字符时明确不可用，不悄悄截断。

GET `/api/ai?task=study&k=pmid:...` 与 GET `task=compare&keys=<JSON 数组>` 只读共享缓存，不取新摘要、不调用模型、不写额度；POST 分别提交 `{task:'study',pmid|doi}` 或 `{task:'compare',items:[{pmid|doi}…]}`，必须是读者明确点击。完整缓存保留 30 天；含缺项的对照缓存保留 1 小时。单篇提取可免费复用于对照，即使停生成或读者额度用满也可阅读已保存结果。引用必须属于对应论文原摘要，中文数字必须属于同一字段引文；机械检查不证明语义完整正确。

读者额度与实际模型尝试分离。锁已占/IP 拒绝不再误扣全站额度，失败请求只退自己预留的读者额度，保留原 UTC 日期，退款幂等。实际模型每次尝试（含失败及最多一次格式/证据重试）在调用前计数且不退款；无法核对计数时停止调用。`MODEL_CALL_CAP` 使用 KV 非原子计数，仍是软限制，不能当作严格费用封顶。全缺摘要不调用模型，结果仍逐篇显示。

诊断读取和写入均只允许固定版本、规范时间/UUID、阶段/错误枚举、有界状态/耗时及布尔超时标志；额外字段删除、坏类型拒绝。最近记录可能陈旧或属于另一并发读者，务必检查 `at`；记录 ID 是尝试标识，尚不是浏览器请求关联 ID。配置齐备、Pages 发布和离线测试均不证明真实模型连通。生产鉴权/端点/模型值不在本轮修改范围；无连接成功证据时保持未验收。

定期维护：每日检查运行失败、安全错误码和实际提供商用量，每周抽查六字段的引句/中文含义、缺摘要比例、缓存复用与重复论文对照，每次服务改动执行四组 Node 离线测试及公开构建/打包门槛。自然语言检索、患者问题、私有全文解读留待独立范围和权限设计。本次无需新建调度或平台绑定。
